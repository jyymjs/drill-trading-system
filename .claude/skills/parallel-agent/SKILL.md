# 分身并行技能 (`/分身`)

## 何时使用

当你需要同时处理多个独立任务，或者一个大任务可以明确分解为互不依赖的子任务时。例如：
- "同时帮我检查这三个文件中的 bug"
- "并行完成 A、B、C 三个模块的代码"
- "多路搜索信息然后汇总"
- "对这个 PR 做安全性、性能、可维护性三个角度的并行审查"

## 使用方法

你可以直接说出需求，也可以使用 `/分身` 命令来触发。自然语言的几种触发方式：

```
/分身 帮我同时做三件事：1. 修复 login.ts 的 bug  2. 重构 utils.ts  3. 添加测试
```

```
并行完成以下任务：...
```

```
启用分身模式，我要同时处理这些：...
```

## 行为机制

当我收到分身请求时，我会：
1. **解析任务** - 识别可并行的子任务
2. **生成子 agent** - 为每个子任务生成一个独立的 AI 分身
3. **并发执行** - 所有子 agent 同时运行，互不干扰
4. **汇总结果** - 收集所有分身的输出，给你一份完整汇报

每个分身拥有独立的上下文、工具和推理能力，彼此隔离。

---

## ⚠️ 重要影响和注意事项

### 1. Token 消耗加速
- 同时运行 N 个分身 → Token 消耗约为串行的 **N 倍级别**
- 每个分身有自己的完整上下文窗口，叠加消耗显著
- **建议**：在需要快速产出时使用，高价值任务优先

### 2. 不能共享上下文
- 分身之间是**隔离的**，A 分身不知道 B 分身做了什么
- 如果一个任务依赖另一个任务的结果，不适合并行
- **建议**：任务之间必须**无依赖关系**才适合分身

### 3. 输出质量
- 每个分身有**独立的推理路径**，质量等同于单独使用
- 但缺少整体协调视角，可能遗漏交叉关联的问题
- **建议**：关键全局决策 - 串行思考；机械并行工作 - 分身加速

### 4. 适用场景对比

| 场景 | 适合分身? | 原因 |
|------|----------|------|
| 多文件独立审查 | ✅ 非常适合 | 文件间无依赖 |
| 并行代码生成 | ✅ 适合 | 模块间接口已定 |
| 多路搜索/研究 | ✅ 非常适合 | 天然独立 |
| 复杂调试 | ❌ 不太适合 | 需全局上下文 |
| 架构设计 | ❌ 不太适合 | 需要一致决策 |
| 多维度审查 | ✅ 适合 | 各维度独立 |
| 批量重构 | ⚠️ 谨慎 | 需要隔离 worktree |

### 5. 对终端的体验影响
- 你会同时看到多个分身的进度
- 最终结果以汇总形式呈现
- 异步通知会在所有分身完成后触发

## 最佳实践

```
# 好的用法 - 独立模块并行
/分身 检查 src/moduleA.ts、src/moduleB.ts、src/moduleC.ts 的代码质量

# 好的用法 - 多维度研究
/分身 分别搜索 React 19、Vue 3.5、Svelte 5 的最新特性

# 需要谨慎的用法 - 有依赖关系
"先做 A 再做 B" → 这是串行，不适合分身

# 需要 worktree 隔离的用法 - 修改文件
"同时在多个文件里改代码" → 分身默认不隔离文件，需要加 worktree 参数
```

## 高级用法

对于大规模并行（10+ 子任务），我会使用 Workflow 编排系统来更高效地调度和管理所有分身。
