# Harness Engineering 工程框架

> 通用 AI 工程化基础设施。所有 `deepseek/` 下的项目自动继承本框架。

## 四个角色

**规划部**（主对话）— 入口+调度中枢，拷问需求、拆解任务、派发工程部/质检部/内审部
**工程部**（子 agent）— 编码实现，独立 worktree 隔离，提审前自跑预检（lint+测试）
**质检部**（子 agent）— 六轴审查：代码质量+业务验收+计划一致性+架构合规+元审查+环境验证
**内审部**（子 agent）— 每 5 任务醒来，审计规则/技能/角色/文档，出模式分析报告

## 核心原则

- Human steers, Agent executes — 人掌舵，Agent 干活
- 规则来自失败 — Agent 犯错才加规则，不写预防性规则
- 脚本优于提示 — 能用代码检查就别用自然语言约束

## 使用方式

1. 直接说需求，规划部自动响应
2. 回答业务层面的拷问
3. 确认规划确认书（纯业务语言，不含代码）
4. 等待自动完成

## 助理中转（2026-08-02 调整）

有助理在场时（助理系统），框架产出**先递交助理审阅**：
- 助理按决策分级自主决定或上呈用户（分级见 `助理系统/助理规则.md` 第十节）
- 规划部/内审部的呈报对象改为助理；无助理场景自动降级为直接呈报用户
- 签字权始终归用户：助理只预审过滤，不替代签字

规则详见 `rules/`，角色详见 `agents/`，技能详见 `.claude/skills/`。
