# 解决 Git 合并冲突

系统性解决合并冲突，确保不丢代码、不破坏逻辑。

## 流程

### 1. 理解冲突

运行 `git status` 查看冲突文件列表，对每个冲突文件：

- 读冲突标记（`<<<<<<<`、`=======`、`>>>>>>>`）
- 理解两个版本的意图：
  - `<<<<<<< HEAD`（当前分支的改动）
  - `>>>>>>> 目标分支`（合并进来的改动）

### 2. 分析冲突类型

| 类型 | 处理方式 |
|------|---------|
| 同位置不同实现 | 选功能正确的版本，或融合两者 |
| 一方删除一方修改 | 确认删除是有意的还是误删 |
| 格式化差异 | 保持一致风格，取正确逻辑 |
| 导入语句冲突 | 保留所有必要导入，去重 |

### 3. 解决规则

- **功能优先**：两个版本功能正确的优先
- **新优于旧**：重构后的代码通常优于旧代码（确认测试通过）
- **有疑问时保留两者**：不确定时保留两份加 TODO 标记，请上级决策
- **不要静默丢代码**：任何删除都要有明确理由

### 4. 验证

```bash
# 确认无冲突残留（git grep 只扫 tracked 文件，不误报 node_modules 等依赖目录）
git grep -n -e "<<<<<<<" -e ">>>>>>>" || echo "✅ 无冲突标记残留"

# 运行测试
项目门禁预检脚本
```

### 5. 提交

```bash
git add <已解决的文件>
git commit -m "merge: 解决与 <分支名> 的冲突"
```

## 检查点

审查合并结果时关注：
- 冲突标记是否全部清除？
- 合并后的逻辑是否完整？（不存在因合并断裂的功能链）
- 是否有不该合并进来的代码？
