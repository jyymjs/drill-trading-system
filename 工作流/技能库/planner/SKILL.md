# 规划技能（执行细则）

总流程（继承偏好→三级拷问→风险评估→冲突检测→出规划书→派发）见 `总理/助理规则.md`（R-033 规划并入主对话）。本技能只存放执行细则与模板，避免与角色文档重复维护。

## 一、三级别拷问

| 级别 | 判断标准 | 必须问的问题示例 |
|------|---------|-----------------|
| **学习请求** | 仅用户主动要求（如"先学习再规划"） | ⚠️ 学习部已清空（R-011 2026-08-05）待重新规划；先告知状态，规划后恢复引导 |
| **必须问** | 影响项目结果的决策 + 灰色地带 | 数据来源是什么？失败时怎么办？范围边界在哪？性能要求？多个方案时选哪个（附推荐）？ |
| **继承确认** | 之前任务已决策过的事 | 沿用上次的数据源/目录/命名约定？ |
| **不问** | 纯技术可实现细节 | 用哪个库、怎么实现——工程部决定 |

**拷问原则**：
- 事实可查（代码/文档/环境）→ 自己查，用 research 后台调研，不打扰用户
- 决策问题 → 才问用户，一次一问，每问附推荐答案
- 灰色地带宁问勿猜：拿不准是"事实"还是"决策"时，倾向问用户；决策问题不足时，把假设清单列出来让用户勾选确认
- 用户给出明确方向后停止拷问，不无限追问

## 二、风险评估

| 风险 | 判定 | 处理 |
|------|------|------|
| **高** | 修改核心逻辑/数据流/公共接口 | 拆小步；先出技术附录验证方案再派发 |
| **中** | 新增模块不碰核心 | 正常粒度 |
| **低** | 格式/注释/重命名 | 可合并多个小改动 |

## 三、依赖图输出格式

```
[子任务A] --同文件冲突--> [串行] [子任务B]
[子任务A] --数据流输出--> [子任务C]
```

- 同文件同区域 → 串行
- 数据流 A 输出 → B 输入 → 串行
- 无依赖 → 默认并行派发（parallel-agent）

## 四、技术附录结构（`.internal/`）

`.internal/{任务名}/技术附录.md`：

```markdown
# 技术附录：{任务名}

## 方案
## 接口设计
## 数据流
## 风险与规避
## 验证方式
```

技术附录给工程部看，可含代码；规划确认书给用户看，纯业务语言。

## 五、规划确认书模板

存放：`资料库/确认书/{日期}-{任务名}.md`（签字后归档）

```markdown
# 规划确认书：{任务名}

## 子任务 N：{简述}
- 标准：{业务语言，可验证}
- 验收：{用户可感知的结果}
```

## 边界

- 继承偏好目录为空时跳过继承步骤，不阻塞
- 任务超 3 个文件或 200 行 → 拆分子任务
- 输出业务语言文档时套用 teach 模板；术语统一进 CONTEXT.md（domain-modeling）
- 学习部与 learn 技能已清空（R-011 2026-08-05）待重新规划；用户主动要求学习时先告知状态
