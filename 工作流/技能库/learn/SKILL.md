# 高效学习技能（执行细则）

系统位置：`学习部/`（独立系统，自包含）。技能本体 `学习部/.claude/skills/learn/SKILL.md`，数据层 `知识库/`（本系统私有）。抓取脚本：

- **B站**：`学习部/scripts/bilibili/fetch.py`
- **网页/论文**：`学习部/scripts/web/fetch_web.py`（任意 URL → 正文提取 → 同规范入库；学术站 arxiv/huggingface 等 WebFetch 受限时必走脚本）
- **找书/下载**：`学习部/scripts/book/find_download.py`（衔接见「五」）

本系统只有**用户与 AI 直接对话**三种形态，无任何子 agent：

| 形态 | 触发 | 流程 | 产出 |
|------|------|------|------|
| **对话式学习** | 给链接/资料/需求/书 | 来源定位 → 抓取 → 对话学习（讲解/质疑/苏格拉底引导/规则提炼）→ 知识接入 | 学习笔记 `知识库/老板知识库/{主题}/` |
| **考问模式** | 用户主动：「考考我 XX / 复盘 XX」 | 出题 → 追问自纠 → 批改 → 归因 → 错题卡 | 错题卡更新 / 复盘报告 |
| **扫库查重** | 用户：「查一下交易部知识库的矛盾」 | 扫描交易部知识库 → 找矛盾/冲突知识 → 找交易部经理讨论 | 矛盾清单 + 讨论结论 |

## 〇、知识库规范与调用协议（先读再执行）

规则只在一处定义，其余一律引用：

- 数据层规则（分类判定/命名/元数据/时效性/可靠性/关联字段/知识卡/局部索引/索引维护/错题卡/知识接入/冲突处理/回流）→ [`知识库/系统/分类规范.md`](../../../知识库/系统/分类规范.md)
- 检索规则（四级检索 + 关联跳转）→ [`知识库/系统/调用协议.md`](../../../知识库/系统/调用协议.md)
- 产出模板 → [`知识库/系统/templates/`](../../../知识库/系统/templates/)（学习笔记/方法建议书/主题知识卡/raw档案）

**调用知识库一律按「定检索面 + 四级检索」协议**（省 token 核心，不读全文找相关性），入口为 `知识库/index.md`（单库：老板知识库。公司资料库已废除 2026-08-03）：

```
第 0 步 定检索面（默认只检本库；跨库须显式声明）→ ① 对库索引入口找主题
② 主题局部 index 拿文件列表（若存在）
③ 文件名 + 元数据判相关性（{日期}-{主题}-{内容要点}-{类型}.md，含「库归属」字段，命中后读元数据块二次确认）
④ 正文（仅通过 ③ 的文件才打开）→ ⑤ 关联跳转（循「关联:」字段进相关主题，可跨库）
```

- raw/ 层不参与检索；主题已有知识卡时**只读知识卡**；时效性按需过滤（详见调用协议）

## 一、对话式学习协议（标准形态）

### 1. 来源定位（宁缺毋滥，如实标注）

- **来源不限条数**：不再限 5 条；按「相关性 + 质量」择优，宁缺毋滥
- **模型训练知识直接参与对话**：AI 掌握的先验知识直接参与讲解与质疑，**不占抓取数**；来源清单中如实标注为「模型知识」
- **外部来源**：B站（实操/经验类首选）→ fetch.py；论文/学术（算法/理论类）→ fetch_web.py；技术博客（教程类）→ fetch_web.py；用户自贴资料 → 直接入库，不检索；书籍 → 走找书流程（见「五」）
- **来源清单如实标注**：每条来源含 标题/类型/可靠性分级/质量信号/链接（模板见方法建议书「二、学习来源」）

### 2. 抓取

- B站 → `python 学习部/scripts/bilibili/fetch.py --url <链接> [--topic <主题路径>]`（输出到 `知识库/{库}/{主题}/raw/`，库=所属产出库）
- 网页/论文 → `python 学习部/scripts/web/fetch_web.py --url <链接>`
- 用户自贴文本 → 直接写 `知识库/{库}/{主题}/raw/manual-{序号}-{内容}-{日期}.md`（库=所属产出库）
- 已存在 → 提示已存在，需 `--force` 才覆盖（知识库去重，勿静默覆盖）

### 3. AI 分类判定 + 命名

按 [`知识库/系统/分类规范.md`](../../../知识库/系统/分类规范.md)「二、三、四」执行：读内容 → 查 index（避免近似主题）→ 判主题路径 → 生成文件名 → 写元数据块（**含时效性/可靠性/关联字段**）。

### 4. 对话学习核心（讲解 → 质疑 → 苏格拉底引导 → 规则提炼）

对每个材料按此顺序进行，产出由对话精华整理：

1. **AI 讲解**：按「三、知识提炼技能」防失真提炼（提炼五问 + 关键信息核对单），每条知识点用**三元组格式**（结论 + 依据 + 条件）
2. **主动质疑材料**：AI 对材料本身做批判性审视——夸大 / 漏洞 / 盲区 / 过时 / 适用边界，讲给用户听，不盲信来源
3. **苏格拉底引导（讲完一个要点，先问后讲）**：每讲完一个要点，**先向用户提问再讲下一个**——
   - 激活旧知识（把新知识挂到用户已懂的知识上）
   - 暴露真盲区（用户答不上来的点 = 真盲区）
   - 防被动灌输、调节学习节奏
   - 盲区处理：当场补讲 + 记入错题卡（格式见分类规范「八」）
4. **规则提炼**：把可复用的知识实时提炼为「情境 → 行动」规则卡（写入产出）
5. **可靠性分级应用**：对话中标注来源可靠性（五级定义见分类规范「四」），低可靠级结论使用时报风险，不静默采信

### 5. 知识接入（五步，写死）

每批产出按 [`分类规范.md`](../../../知识库/系统/分类规范.md)「九、知识接入协议」落地：**定位 → 对接（四级检索同主题旧产出）→ 判定关系（互补/升级/冲突/重复，写明依据）→ 落地（含关联字段互链）→ 索引**。任何产出不得静默入库；冲突按四步处理。

### 6. 产出（按模板）

- 给链接/资料 → 学习笔记（模板：`知识库/系统/templates/学习笔记模板.md`）——含 核心要点 / 材料批判结论 / 对我的意义 / **验证计划（含闭卷复述）** / 规则卡 / 关联字段；落 **`知识库/老板知识库/{主题}/`**
- 给需求/资料 → 学习笔记（模板：`知识库/系统/templates/学习笔记模板.md`）——含 核心要点 / 材料批判结论 / 对我的意义 / 验证计划 / 规则卡 / 关联字段；落 **`知识库/老板知识库/{主题}/`**（公司资料库已废除，产出统一入老板库）

### 7. 更新索引

按 [`分类规范.md`](../../../知识库/系统/分类规范.md)「七、索引维护规范」更新**所属库**索引入口（新主题加入口；追加条目；触发 O5 局部索引 / O1 知识卡合并）。

## 二、考问模式协议（用户主动触发）

**触发**：用户说「考考我 XX / 复盘 XX」→ AI 按定检索面 + 四级检索调 知识卡 + 错题卡（`知识库/老板知识库/{主题}/错题卡.md`）。

### 流程

```
出题先问后答 → 产婆式追问自纠 → 防迎合批改 → 归因 → 错题卡更新
```

1. **出题先问后答**：先让用户尝试作答/先问清想考哪块，再出题；不直接给答案
2. **产婆式追问自纠**：答错不直接纠正，用追问引导用户自己发现矛盾；**连续 2 次卡壳 → 给一条线索**（仍不替用户说出答案）
3. **防迎合批改**：批改**先挑错后认可**——先指出错误/不足并讲清原因，再肯定对的部分；不得只夸不批
4. **归因（写死，二选一）**：
   - **提炼失真**（笔记/知识卡本身讲错了或漏了）→ 当场回补修正笔记，并在错题卡记"归因：提炼失真 → 已修笔记"
   - **遗忘**（笔记没问题，用户忘了）→ 记入错题卡
5. **错题卡更新**：按 [`分类规范.md`](../../../知识库/系统/分类规范.md)「八、错题卡规范」记录——题目 / **推理断点**（断在哪一步）/ 归因 / 复习计划（第 1/7/30 天）/ 状态
   - **间隔重复 1/7/30**：第 1 天、第 7 天、第 30 天各复习一次；通过 = 用户**自己重建推理链成功**（AI 只引导不提示）
   - **毕业机制**：三次全部重建通过 → 标记"已掌握"移入 `archive/` 归档（不删除）；任一次失败 → 停留并重新计间隔（防错题卡膨胀）
6. **可选费曼复盘**：用户当老师讲课，AI 当**严苛学生**——找逻辑缺口、追问细节、要求举例，逼出真懂

## 三、知识提炼技能（防失真核心）

> 提炼总结是系统命脉，质量靠「过程防失真 → 产出分级 → 结果验证」三道防线。

### 提炼五问（每条知识点提炼时过一遍）

1. **核心主张**：材料到底在说什么？（一句话）
2. **依据**：主张靠什么支撑？（数据/实验/案例/推理）
3. **事实 vs 观点 vs 推论**：哪部分是事实、哪部分是作者观点、哪部分是推论？
4. **适用条件**：在什么条件下才成立？（边界/前提/限制）
5. **保真**：我的提炼与原意一致吗？（对照核对单）

### 抗失真三查

1. **数字原样**：数字/百分比/时间原样保留，不得约整美化
2. **限定词保留**："可能/部分/特定场景下"等限定词不得删——删掉就夸大了结论
3. **独立可读**：每条知识点脱离上下文也能读懂（不自带未解释缩写/暗指）

### 关键信息核对单（提炼前抽、提炼后核、逐项打勾）

- **提炼前**：把原文的 **数字 / 专名 / 日期 / 条件 / 结论** 抽成清单
- **提炼中**：按提炼五问 + 抗失真三查进行
- **提炼后**：逐项打勾核对——清单每项必须在知识点中找到，**缺项回补**
- **兜底**：raw 全文保真 + 章节锚点（书籍每条知识点标"第X章第X节"），任何压缩可回原文核对
- **诚实边界**：论述细节必然压缩；结论/依据/条件/数字/专名由核对单保证不丢

### 三元组格式

每条知识点 = **结论 + 依据 + 条件**（缺一即不完整，宁缺毋滥）。

### 考问归因接入

考问模式中用户答错，若归因是**提炼失真** → 回到本条技能流程重新提炼并回补笔记（闭环）。

## 四、找书 / 拆书衔接

- **找书**：`scripts/book/find_download.py`（内置 38 渠道 + 渠道健康度台账 `channels_health.json`）
  - 流程：AI 搜索候选 → 候选清单**必含 书名+作者+版本+渠道**（同名书多，**用户钦定后才下载**）→ 下载 → 类型校验（PDF/EPUB/TXT/MOBI/AZW3）→ 空文件检测 → 存 `知识库/老板知识库/{主题}/raw/`（拆书产出为学习笔记，落老板库）
  - 风控与健康度规则：连续失败 5 次自动淘汰 / 403 三次仅提示不淘汰（镜像变动）/ 成功一次复活；具体以脚本 `--help` 与阶段三脚本文档为准
- **拆书**：书籍 raw 分卷存 `知识库/老板知识库/{主题}/raw/`（`书籍-<书名>-第X章-<章节标题>-<日期>.md`），**每条知识点带章节锚点**；扫描版 PDF 标注"需文字版"，OCR 不纳入首版
- 找书/拆书工具的具体协议在阶段三脚本文档（`scripts/book/`）定义，本技能只做流程衔接

## 五、资料库复盘协议

**触发**：用户说「复盘资料库 / 资料库体检」；或系统提示（碎片堆积/冲突未决时）。

### 四步

1. **体检**：用合规检查器扫描全库（文件名规范 / 元数据完整性 / 索引一致性 / 近似主题 / 同主题冲突 / 分层混放 / 关联字段完整性）——检查器为阶段三脚本，落地前由 AI 人工按上述七类逐项核查
2. **盘点**：读 `知识库/index.md` + 各主题知识卡，审结构合理性（主题过碎/过杂/命名不一致/碎片堆积）
3. **整理**：分类修正（改目录 + 更新索引）/ 碎片合并（知识卡升版）/ 过时标注（**只标注不删除**）/ 冲突处理（四步，见分类规范「九」）/ 关联补链（互链缺口）/ 索引校对（索引与实际文件一致）
4. **报告**：输出复盘报告（存 `知识库/复盘/{日期}-资料库复盘-复盘报告.md`），含**体检结果 + NEXT 清单**

### NEXT 清单（复盘驱动下一轮学习）

| 结构信号 | 建议动作 |
|---------|---------|
| 碎片 ≥5 无知识卡 | 建议系统学一次（对话式学习补齐） |
| 未裁决冲突 | 学新内容来裁决 |
| 短期知识卡过时 | 重学更新 |
| 活跃领域久未更新 | 建议复习（考问模式） |

### 三原则

1. **只标注不删除**：过时/废弃内容一律标注（"过时/已被替代"），不物理删除
2. **重大决策用户拍板**：目录重构/删除/知识卡大规模合并等需用户确认后才执行
3. **复盘驱动下一轮学习**：NEXT 清单 = 学习需求，用户选定 → 触发对话式学习 → 新产出走知识接入 → 下次复盘验证（闭环）

### 周期复盘挂钩（R-001 · 与总裁办周复盘/月体检联动）

- **周复盘顺带检查**：先查素材台账（`知识库/复盘/素材处理台账.md`）——本周有无可入库素材未处理；有 → 建议主题进入系统学习模式（启动前必查台账防重复提炼）
- **月体检必查「培训部学习建议」项**：学习建议主题清单 + 素材台账核对 + 双库索引与实际产出核对（去重验证）
- 素材台账：已处理素材不得重复提炼；台账与实际产出一致是复盘检查项

## 六、学习闭环

- **验证计划执行**：学习产出必带验证计划（含闭卷复述 + 应用验证，见笔记模板「验证计划」）；闭卷复述不过关 → 回 raw 补读重炼；考问模式是验证手段之一
- **回流接通**：学习 / 考问 / 拆书 / 复盘产出的知识**全部按规范回流入库**（分类规范「十」）——AI 分类 + 命名 + 元数据（含可靠性/关联）→ 知识接入五步 → 索引维护；回流不是可选动作

## 七、风控要求（唯一源，调用 fetch.py / fetch_web.py / find_download.py 时）

- **请求间隔 ≥2 秒**（脚本已内置 `--sleep`，默认 2.0）
- 遇风控（接口返回 -412 / -403 / 412）**立即停止**，读提示后降频或隔日再抓，**不重试轰炸**；403/验证码页不绕过，提示浏览器手动下载
- **SESSDATA 只读不写**：只用于读取字幕等只读接口，绝不调用任何写接口（评论/点赞/关注等一律不发）
- SESSDATA 存 `学习部/scripts/bilibili/config.local.json`（已 gitignore，不提交）；无 SESSDATA 时脚本自动降级游客模式（仅信息+弹幕+评论，字幕提示需登录）
- **SESSDATA 过期检测**：抓取时若登录态失效（nav 接口 isLogin=False）→ 明确提示「SESSDATA 已过期，请更新 config.local.json」，不静默降级
- 抓取失败重试：网络抖动/5xx 自动重试一次；空文件（<1KB）判失败删除

## 八、边界声明（与 research 技能区分）

| | learn（本技能） | research |
|--|----------------|----------|
| 目的 | 多源**方法学习** / 独立知识总结 / 复习考问 | 查证**特定事实**（数据、文档、API 现状） |
| 产出 | 学习笔记 / 方法建议书 / 错题卡 / 复盘报告 | 事实核查结论 |

- 用户要「学一下 X 有哪些做法 / 怎么入门」→ learn
- 需要核实「某库是否支持 Y、某参数当前值」→ research
- 对话式学习的独立总结（给链接要笔记）归 learn，不归 research
