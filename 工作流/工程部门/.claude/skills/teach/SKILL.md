# 知识传递

将技术细节转化为业务语言。受众是非技术背景的业务人员。

## 核心原则

- **业务语言优先**：说"系统会自动检测重复数据"而不是"系统做了去重哈希映射"
- **类比优于术语**：用日常场景类比技术概念
- **用"做什么"而非"怎么做"**：说实现效果，不说实现原理

## 文档编写模板

### 功能说明（给业务人员看）

```
## {功能名}

**做什么**：{一句话说清功能}

**什么时候用**：{触发场景}

**看到什么结果**：{用户可见的产出}

**需要注意**：{边界/限制/前提}
```

### 变更说明（给业务人员看）

```
## 改了什么

- 改了：{改了啥，业务语言}
- 原因：{为什么改}
- 影响：{对现有功能有什么影响，无影响则写"无"}
```

## 教程/指南编写

按用户操作路径组织，而非按代码结构：

✅ 好："点击'开始扫描'按钮 → 等待约 7 分钟 → 在结果表里看评级"
❌ 差："main.py 调用 scanner.scan() 后触发 5 线程并发..."

## 注释规范

代码注释也用业务语言：
```python
# ✅ 好
# 当股票连续3天缩量但价格不跌时，标记为"量缩价稳"信号

# ❌ 差
# threshold = 3 and vol_decreasing and not price_decreasing → flag = 1
```
