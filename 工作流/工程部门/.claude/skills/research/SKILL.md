# 研究调查

**定位**：助理（主对话）拷问阶段的事实核查（"这个库支持 X 吗？""这个接口的签名是什么？"）与一般研究任务。事实类问题自己查，不打扰用户。

**与 grilling 的边界**：事实可查环境（代码/文档/网络）→ 用本技能；决策偏好问题 → 用 grilling 问用户。

## 流程

1. **明确问题**：把模糊问题改写成可查证的问题（"X 是否支持 Y？在什么版本？"）
2. **派后台 agent**：用 Agent 工具派 Explore/general-purpose 子 agent 调研，主对话继续其他工作
3. **一手来源优先**：官方文档、源码、spec、API 文档 > 二手转述（博客转述官方内容算二手）。每个结论追溯到它的来源
4. **写报告**：保存到 `工程部门/支撑/文档/reports/{日期}-{主题}.md`，按下方模板
5. **汇报**：向用户口头汇报结论摘要（含置信度）

## 输出模板

```markdown
# 研究：{主题}

- 日期：YYYY-MM-DD
- 问题：{可查证的问题}

## 结论
{一句话结论}（置信度：高/中/低）

## 方法
{查了什么、检索路径、用到的来源类型}

## 发现
- **{发现}** — 来源：[官方文档](url) / {文件路径}
- 每一条发现附来源

## 未覆盖
{查不到的、留待后续的}
```

## 质量标准

- **置信度声明**：高（一手来源直接确认）/ 中（多来源一致）/ 低（推断或来源不足）
- **时间盒**：单个调研 ≤ 30 分钟（或用户指定），超时先交部分结论
- **查不到就回退**：查不到时明确说"查不到"，并回退为向用户提问（转 grilling），不编造
- **不引用不可验证来源**：无链接/无文件路径的结论不写进报告

## 何时不用

- 决策问题（该选哪个方案）→ grilling
- 代码内事实（某个函数怎么实现）→ 直接读代码，不需要研究
