# Harness Engineering 工程框架

> 通用 AI 工程化基础设施。所有 `deepseek/` 下的项目自动继承本框架。

## 三个角色 + 同级优化部门

**规划部**（主对话）— 入口+调度中枢，拷问需求、拆解任务、派发工程部/质检部
**工程部**（子 agent）— 编码实现，独立 worktree 隔离，提审前自跑预检（lint+测试）
**质检部**（子 agent）— 六轴审查：代码质量+业务验收+计划一致性+架构合规+元审查+环境验证
**优化部门**（同级一级部门，见 `../优化部门/`）— 系统动力引擎：稳定/收口/告知/建议；问题台账+审计流程（原内审部，2026-08-04 升级）

## 核心原则

- Human steers, Agent executes — 人掌舵，Agent 干活
- 规则来自失败 — Agent 犯错才加规则，不写预防性规则
- 脚本优于提示 — 能用代码检查就别用自然语言约束

## 使用方式

1. 直接说需求，规划部自动响应
2. 回答业务层面的拷问
3. 确认规划确认书（纯业务语言，不含代码）
4. 等待自动完成

## 呈报对象（2026-08-04 调整：取消助理中转）

框架产出**直接呈报用户**（原"先递交助理审阅"已取消——主对话合并业务+工程双职能，不再有中转层）：
- 签字权始终归用户：任何 AI 角色只建议与转呈，不替代签字
- 业务操作规范沿用 `总理/助理规则.md`（记忆/待办/确认/日报，由主对话直接执行）

规则详见 `规则/`，角色详见 `规划/执行/测试/内审/`，组织架构见 `组织架构.md`，技能详见 `.claude/skills/`（链接至 `技能库/`）。
