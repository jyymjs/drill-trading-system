# R-034B 日报/周报/月报体系方案（2026-08-07 追加）

## 一、现状研究结论（三报现状：全部"纯对话、零落盘"）

| 报告 | 现状 | 内容 | 问题 |
|---|---|---|---|
| **日报** | 被动触发（老板说"日报"才出）| 已办/待办/逾期/在办/想法池（助理规则第六节）| 不落盘：说过就过，历史无法追溯；内容只有任务向，缺交易/系统状态 |
| **周报** | **R-033 已废除**，全库无周报产出 | — | 删除后"周度复盘"空档：交易复盘（记忆里 69 份周会学习）与体系周检无人汇总 |
| **月报/月体检** | 纯对话式（R-003 目标对标 + 记忆月体检 + 注册表巡检）| 目标进度对标（达标/差距/证据）| **无固定模板、无落盘档案**：月体检说过就过，跨月无法对照 |

**共性问题**：① 零落盘 → 无法追溯/对照 ② 内容割裂（任务/交易/目标各说各话）③ 全被动触发 → 老板不说就没有 ④ 无自动化。

## 二、优化方案（三层金字塔：执行层/复盘层/战略层）

### 日报（执行层 · 每日）
- **保留**：老板说"日报"即时输出（快）
- **新增**：每晚 19:30 自动落盘 `产出/输出/报告/日报_YYYYMMDD.md`（老板醒来可看）
- **内容三合一**：① 任务（已办/待办/逾期）② 交易（执行卡摘要：有无挂单/环境档/账户校验状态）③ 系统（数据新鲜度/健康检查/运行台账异常数）
- 开场第 1 步检查：日报已生成且含"⚠️"标记 → 先呈报

### 周报（复盘层 · 每周日 · 轻量恢复）
- **建议恢复轻量版**（10 分钟模板填充，非长篇）：
  - 本周交易：笔数/成交 R/持仓状态/执行卡是否每天正常
  - 本周任务：完成/卡点
  - 本周系统：运行台账新增事件（无→"无异常"）
  - 本周学习/想法池变化（一句话）
- 落盘 `产出/输出/报告/周报_YYYYMMDD.md`；周日晚自动带出，老板说"不要"可跳过
- **理由**：交易复盘是周维度的事（策略/教学周会本来按周），周报恢复轻量版补上空档

### 月报（战略层 · 每月 1 日 · 月体检升级为档案）
- 固定模板落盘 `产出/输出/报告/月体检_YYYYMM.md`，**五检**：
  1. 目标进度对标（R-003 已有，达标/差距/证据）
  2. 交易月报：笔数/收益/avgR/蒙卡对照/执行卡摘要
  3. 记忆体检：待检清单/清理（三信号）
  4. 资产巡检：注册表异常/计划任务/备份状态
  5. **规则执行检查**（R-034 新增）：本方案 10 项机制逐条核"是否在跑"
- 触发：每月首次对话自动带出；季初月（8/11/2/5）顺带季度拆解（R-003 已有）

## 三、验收标准（可测）
1. 日报每晚自动落盘（19:30 计划任务或开场补生成），含任务/交易/系统三块，**≤8 行**，异常才展开
2. 周报模板（**复用旧版三节**：本周任务/错误台账周呈报/交易系统进展）周日晚带出可跳过；落盘归档，**≤15 行**
3. 月体检五检模板落盘（目标/交易/记忆/资产/规则执行检查），**一页内**
4. 三报目录统一 `产出/输出/报告/`，文件名带日期可追溯
5. **试用期 4 周**：周报/月报先跑 4 周，老板不看即砍（消灭无效规则于试用期）
6. 原则：模板极简、"无变化就写无变化"（N/A 文化）、异常清单不是流水账

# R-034C 飞书紧急推送方案（2026-08-07 追加 · 老板确认）

## 一、设计原则（关键修正）
- **推送触发点在脚本层，不经过总助**：紧急检测写进计划任务脚本（PowerShell），异常时脚本直接调飞书 API 发消息——**不依赖 Claude 会话在线**
- 通道区分：对话通道（cc-connect，需在线）≠ 推送通道（飞书 API，脚本直发，仅需电脑开机）

## 二、推送内容（仅 3 类紧急）
1. 健康检查异常（数据不新鲜 / 执行卡缺失 / 计划任务失败）
2. 交易熔断（连败≥5 / 账户异常 / 持仓集中）
3. 资金类到期（注入日 / 还款类）

## 三、实现要点
- 复用 cc-connect 飞书应用凭证（app_id/app_secret，config.toml，勿外泄）→ tenant_access_token → `im/v1/messages` 发单聊
- 写在 `每日扫描.ps1` 健康检查段（R-034 主体第 3 项同处）
- 时间窗口：避开 7:30-16:00 睡眠时段（紧急除外）
- 非紧急只落盘+开场带出，不推

## 四、边界（如实）
- 电脑关机 = 无法推送（物理边界，不引云端）
- 推送只负责"叫醒"，处置仍由老板开对话交总助

# R-034D 定时任务链式验证 + 人格防包办（2026-08-07 追加 · 老板确认）

## 一、定时任务有效性（链式验证，不靠看日志）
| 层 | 验证器 | 触发 |
|---|---|---|
| 产物证据 | 执行卡_今日.md 存在 = 扫描跑过 | 每日 |
| 终检 | 19:30 日报含执行卡摘要，缺失→标⚠️ | 每日 |
| 开场快验 | daily_update.log / daily_scan.log 最后修改时间 >2 天 → 上呈 | 每次会话 |
| 月度终检 | 月体检 schtasks /query 核对任务状态 | 每月 |
| 手动触发测试 | 任务改后立即 schtasks /run 验证配置 | 改动时 |

## 二、人格触发与防包办
- **强制触发条件（禁区铁律强化）**：任何落盘改动 → 一律人格链（不分大小）；交易分析→投资研究员；实验→实验追踪器；可视化→UI设计师；系统升级→架构师；S 级（单文件/低风险/无落盘）才总助直办
- **判断标准**：是否落盘 / 是否影响交易 / 是否跨系统——任一"是"→ 走人格链
- **留痕**：交付物注明"经人格链"或"总助直办（S 级）"；台账/日报可见
- **月报包办率统计**：月体检规则执行节统计本月需求 N / 走人格链 X / 直办 Y——包办率老板可见
- 教训：2026-08-07 批处理修复系总助直办未走人格链（老板拍板但流程未走），已承认并改进
