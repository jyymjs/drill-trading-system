## 一、为什么做（业务目标）

R-001 讨论暴露出现行机制短板：规划者只被动回应审阅意见、讨论不留痕、老板看不到分歧点。目标是让规划确认书的讨论**双向、留痕、透明**，老板只拍真正需要拍板的板。

## 二、已拍板四项核心升级（2026-08-02 老板确认）

| # | 升级项 | 说明 |
|---|---|---|
| ① | 规划者补充建议 | 规划者可在确认书中主动补充建议，不限于被动回应审阅 |
| ② | 双向讨论（≤3 轮） | 助理与规划者双向你来我往，替代单向"出稿→打回" |
| ③ | 采纳/驳回标注 | 互发文件逐条标注采纳/驳回+理由，可追溯 |
| ④ | 呈报注明三项 | 呈报老板注明：更新事项 + 功能介绍 + 分歧意见 |

## 三、优化建议（4 条，老板指示一并写入）

> 原拟第 ① 条"分级适配（S/M 轻量版讨论）"经老板指出撤销：S/M 级需求不经规划部（S 直接执行、M 出迷你方案），确认书双向讨论**天然仅作用于 L 级流程**，无需分级适配。

### ① 分歧分级分流——减少老板被打扰
- 纯技术分歧 → A 档助理定
- 执行类分歧 → B 档先办后报
- 业务/方向分歧 → C 档上呈（附助理建议）
- 依据：决策分级 A/B/C（助理规则第十节）

### ② 分歧决策清单模板——第 3 轮兜底有抓手
第 3 轮未收敛时按固定模板上呈：
```
分歧点 / 双方立场 / 影响面 / 助理建议 / 请老板拍板
```

### ③ 确认书变更日志——版本演进留痕
- 确认书模板加"变更日志"章节：v1.0 → v1.x 每版记录（改了什么 / 谁的意见 / 采纳或驳回）
- R-001 已实践版本号递增（v1.2），规范化为固定章节

### ④ 试点验证——机制落地不裸奔
- R-002 实施后，用下一个真实 L 级需求试点
- 内审部月审计顺带检查讨论留痕质量
- 2 周后评估微调再全面铺开
