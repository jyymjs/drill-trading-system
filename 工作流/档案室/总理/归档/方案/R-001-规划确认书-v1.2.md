## 一、需求理解摘要

培训部从"老板的个人自学平台"升级为**双轨制**：人学轨道（保留对话式学习/考问，老板自学）+ 系统学轨道（老板提功能需求时，培训部联网抓取提炼《方法建议书》，为规划部供料，形成"系统学 → 公司库 → 规划部复用"闭环）。知识库拆「老板知识库/公司资料库」双库，调用严格区分、相关可联合（助理判定）；交易部成果须经培训部重新学习审核（闸门）后入库——**培训部学习成果经闸门检查单（培训部自行审核）后直接入库，无需老板逐个确认（R5 豁免，仅限此场景）**；配套素材去重台账 + 周期复盘挂钩 + 一次端到端试点。纯对话式约束，research 不动，交易系统文件零接触。

## 二、方案要点

### a. 双库目录结构
```
知识库/
├── index.md              ← 双索引入口
├── 系统/                 ← 协议/规范/模板（不分库）
├── 复盘/                 ← 体检报告 + 素材处理台账（元层，不分库）
├── 老板知识库/           ← 学习笔记/错题卡/raw（AI学习方法 3 篇+错题卡 / AI编程 1 篇）
└── 公司资料库/           ← 方法建议书（AI学习方法 2 篇）
```
归位按产出类型：建议书→公司库、笔记+错题卡→老板库；**raw 跟随精炼后的文件走（Q2 老板拍板）**：精炼成笔记→raw 入老板库，精炼成建议书→raw 入公司库，同一 raw 服务两库产出则两库各存一份；外部素材不拷入（只读引用）。

### b. 调用协议
- 检索第 0 步"定检索面"：默认只检本库，跨库须显式声明
- 产出带「库归属」标记；相关联合由助理判定，联合产出入公司库，老板库内容仅参考不抄入
- 权限：老板库=老板+助理；公司库=老板+助理+规划部/工程部（协议级，Q3）

### c. 系统学习模式（learn 第三形态）
- 需求触发式（无主动推送）；时间盒 ≤30 分钟（检索5/抓取10/提炼10/入库5）；来源≤5条、全文抓取≤3条；超时出半成品

### d. 入库闸门
- 交易部成果/外部素材 → 不得直接入库 → 系统学习模式重新提炼 → 入库检查单（培训部自审）→ **直接入公司库（免老板确认，R5 豁免仅限此场景）**
- 豁免边界：其他写动作（规则/文件修改等）仍按 R5 需老板确认

### e. 周期复盘
- 周复盘顺带检查（先查素材台账）；月体检必查"培训部学习建议"

### f. 端到端试点
- 素材：3 篇周会稿（2024-06-22 / 07-20 / 08-03，只读）→ 《交易周会方法建议书》→ 闸门自审 → 直接入公司库；同时建立素材处理台账（3 条记录，去重验证）

### g. 附带更新
- 组织架构.md 培训部双职能；学习部 CLAUDE.md / learner.md / 根级 CLAUDE.md 门面同步
