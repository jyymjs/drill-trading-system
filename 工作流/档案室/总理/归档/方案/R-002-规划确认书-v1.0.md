## 一、做什么（业务语言）

R-001 讨论暴露出旧机制短板：规划者只被动回应审阅、讨论不留痕、老板看不到分歧点。本次把「规划确认书」的讨论从单向"出稿→打回"升级为**双向、留痕、透明**的机制，让老板只拍真正需要拍板的板。

一句话：**让讨论有来有往、每条意见有交代、每次修改有记录、每个分歧有归处。**

## 二、落地细则（8 项全量纳入，源自已确认迷你方案）

### 升级① 规划者补充建议

- **做什么**：规划者出稿时或讨论中，可主动补充建议（技术可行性提示、备选做法、风险提醒），不再只被动回应助理的审阅意见。
- **什么时候用**：讨论的任何一轮中，规划者发现值得说的内容即可提出。
- **看到什么结果**：确认书里除了回答审阅意见，还能看到规划者主动提出的建议及其处置结果。
- **需要注意**：建议仅作补充，不改变签字权归属（签字权始终归老板）。

### 升级② 双向讨论（≤3 轮）

- **做什么**：助理与规划者你来我往讨论，替代单向"出稿→打回"。完整流程：规划者出稿 → 助理审阅（逐条标注意见）→ 规划者逐条回应或修订 → 助理复核 → 循环，**上限 3 轮**。
- **什么时候用**：每份规划确认书的讨论修订环节。
- **看到什么结果**：第 3 轮仍未收敛时，强制收敛为决策清单上呈老板（不再无限往返）。
- **需要注意**：3 轮是硬上限，防止讨论拖沓；第 3 轮兜底走优化②模板。

### 升级③ 采纳/驳回标注

- **做什么**：互发文件（确认书 / 审阅意见）中，每条意见逐条标注「采纳 / 驳回 + 理由」。
- **看到什么结果**：任何一条审阅意见，都能查到它被采纳还是驳回、为什么，全程可追溯。
- **需要注意**：无未标注意见是验收硬标准（见第五节第 3 条）。

### 升级④ 呈报注明三项

- **做什么**：呈报老板的材料必须注明三项：**更新事项**（这次改了什么）+ **功能介绍**（新机制干什么用）+ **分歧意见**（双方没谈拢的点）。
- **看到什么结果**：老板看呈报材料一眼就明白：变了什么、有什么用、哪些还没定。
- **需要注意**：此项由助理在日常呈报动作中落实，规则写入第三节 SOP。

### 优化① 分歧分级分流（减少老板被打扰）

- **做什么**：讨论中出现的分歧按性质分流，能定的助理定，定不了的才上呈：
  - **纯技术分歧**（用哪个实现方式）→ **A 档**助理定，事后汇报
  - **执行类分歧**（先做哪步、排期）→ **B 档**先办后报
  - **业务/方向分歧**（值不值得做、是不是老板要的）→ **C 档**上呈，附助理建议
- **依据**：助理规则第十节决策分级 A/B/C，此处复用，不新造分级。
- **需要注意**：拿不准属于哪档 → 一律按 C 档上呈（宁多呈不越权）。

### 优化② 分歧决策清单模板（第 3 轮兜底抓手）

- **做什么**：第 3 轮讨论未收敛时，按固定模板上呈老板，五个固定栏目：

```
分歧点 / 双方立场 / 影响面 / 助理建议 / 请老板拍板
```

- **看到什么结果**：老板收到的不再是零散对话，而是一张可直接拍板的清单。

### 优化③ 确认书变更日志（版本演进留痕）

- **做什么**：规划确认书模板新增固定「变更日志」章节，v1.0 → v1.x 每版记录：**改了什么 / 谁的意见 / 采纳或驳回**。
- **背景**：R-001 已实践版本号递增（v1.2），本次规范化为固定章节，不再靠自觉。
- **看到什么结果**：任何版本的确认书，改动来龙去脉一查便知。

### 优化④ 试点验证（机制落地不裸奔）

- **做什么**：R-002 实施后，**用下一个真实 L 级需求**全程走新机制试点，2 周后评估微调，再全面铺开。
- **谁检查**：内审部月审计顺带检查讨论留痕质量（作为月审计常规项）。
- **需要注意**：试点前不宣称"已全面生效"；评估结论（继续/微调/回退）写入结案归因。

## 四、子任务清单

### 子任务 A：规划.md 机制升级（规划部）
- 标准：规划者职责与流程中写入——①可主动补充建议（不限于回应审阅）；②双向讨论 ≤3 轮、第 3 轮未收敛转决策清单；③互发文件逐条标注采纳/驳回+理由；④确认书模板新增"变更日志"章节（每版记录改了什么/谁的意见/采纳或驳回，版本 v1.0→v1.x 递增）
- 验收：阅读 规划.md 可见上述全部规则；实施后产出的第一份确认书（试点）自带"变更日志"章节

### 子任务 B：CLAUDE.md 需求流转同步（规划部，条件性）
- 标准：v1 评审时检查框架入口描述（使用方式/助理中转）与新版讨论机制是否一致；一致 → 跳过并登记原因；不一致 → 同步描述
- 验收：框架入口描述与实际流程一致；跳过时台账有明确原因记录
- 条件：是否执行由助理在评审时决定（A 档），不单独上呈老板

### 子任务 C：助理规则.md 第三节 ④ 讨论修订环节改写（助理侧）
- 标准：④ 环节写入——双向讨论 ≤3 轮；互发文件逐条标注采纳/驳回+理由；分歧按 A/B/C 分级分流（技术→A、执行→B、业务/方向→C）；第 3 轮未收敛按固定模板上呈（分歧点/双方立场/影响面/助理建议/请老板拍板）；呈报老板注明三项（更新事项/功能介绍/分歧意见）
- 验收：阅读第三节可见新机制全貌（与子任务 A 规则互相咬合，无矛盾）；助理实操按新流程执行
