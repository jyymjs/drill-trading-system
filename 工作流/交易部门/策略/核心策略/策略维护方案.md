# 策略维护方案（V4 现行 · 2026-08-07 老板拍板"制定后续计划的维护方案"· T-029 落地）

> 用途：当前策略（V4，唯一现行）今后的**维护机制**——什么能改、怎么改、改完怎么验证、谁拍板。
> 整合既有铁律：方法论铁律（抽样实验必须全量复核）/ 对照实验 / 质检流程 / 签字权 / 补完计划授权。
> 关联：[[策略修改概览.md]]（M-编号演进）｜[[策略版本存档.md]]（定义）｜补完计划执行记录｜错误台账

## 一、修改分类（三级）

| 级别 | 范围 | 例子 | 决策权 |
|---|---|---|---|
| **微调** | 参数数值（阈值/周期/比例） | dn_confirm 1.5→1.6、动量 10%→8% | 助理自主（数据支撑+全量复核通过），周报呈报 |
| **改进** | 规则语义调整（实现方式/边界） | G4 夹角判定修正、确认规则再放宽 | 助理自主 + 老板知情（数据说话） |
| **改版** | 结构级（评级体系/入场逻辑重构）| V3 立项 | **老板签字**（实盘线开启/改版/暂停均归老板） |

## 二、修改流程（铁律六步）

```
发现问题 → ① 对照实验（数据支撑，先跑数据不说话）
         → ② 全量复核（方法论铁律：抽样结论必须全量验证）
         → ③ 质检（六轴验收，出具通过意见）
         → ④ 签字（微调=授权内自主；改版=老板"确认"二字）
         → ⑤ 生效 + 登记（修改概览 M-编号持续编号 + 版本存档 + 记忆同步）
         → ⑥ 报告（周报呈报；数据/依据/结论全录）
```

## 三、验证门槛（按级别分层）

| 级别 | 门槛 |
|---|---|
| 微调 | 全量回测对照（同链路）+ 蒙卡 10000 次 + 520 测试回归 + 口径铁律（回撤一律真实/峰值） |
| 改进 | 同微调 + 分布诊断（依赖大赢家变化核对） |
| 改版 | 全面测试四组（test_current_full 全量：回测全量/资金限制 + 蒙卡信号层/资金层）+ 双件套蒙卡 + 质检六轴 + 新旧对照（不劣于旧版才放行——最后全面测试 B 总闸门模式） |

## 四、版本管理原则（V1 清除后确立）

1. **V4 唯一现行，版本不并行**：新版本替换旧版本，旧版定义留档（策略版本存档）供追溯，不保留"可对比的平行方案"
2. **V3 立项条件**：结构级改动（评级/入场重构）或微调+改进累计到重大行为变化（修改概览 M-编号或行为漂移显著）→ 老板拍板立项
3. 任何版本切换 = 老板签字 + 全面测试总闸门（不劣于现行才放行）

## 五、维护节奏

| 触发 | 内容 |
|---|---|
| **事件驱动**（首要） | 实盘数据异常（连亏超 P99 12 笔/回撤超 18% 警戒/盈利结构与预期偏差）→ 评估是否策略问题 |
| 实盘检查点 | 50 笔（查执行质量）/ 100 笔（判收益）——数据校准：重跑对照实验验证回测预期 |
| 定期 | 周报策略观察项 + 月体检联动（记忆体检机制） |
| 提案 | 全员（助理/工程/质检/trader）发现优化空间 → 提案箱 → 助理审核 → 按级别走流程 |

## 六、实盘数据监控（维护输入）

- **R 值曲线**（r_curve.py）：每笔 R 记录 → 与回测分布对照（蒙卡 P50/P95 区间）
- **执行卡系统状态行**：连败计数/持仓集中/账户校验（熔断警报）
- **偏差预警**：实盘累计 R 低于蒙卡最差 5% 区间（-1.1R 单笔分布）→ 触发排查

## 七、档案与追溯

- 每次修改：修改概览 M-编号（改了什么/为什么/数据/状态）+ 补完计划执行记录（决策依据）
- 数据/报告：产出/输出/（对照实验报告统一命名）
- git 提交：每次生效可回退（保留历史）
