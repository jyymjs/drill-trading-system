## 一、业务目标

**现状痛点**：策略 V2 是"从今天往后看"的选股器——`scan`/`diagnose` 只能对**当前**行情输出 S/A/B/C 评级，无法回答"这套 6 条件体系在历史上到底灵不灵"。交易决策（评级、触发价、止损价）没有历史胜率背书，等于蒙眼开枪。

**本需求要什么**：造一台"时光机"——把策略 V2 放回**任意历史区间**的行情里跑，逐日/逐股判断"如果当时在那个时点扫描，会选出哪些股票、什么评级"，再跟踪每一笔信号**后续的实际涨跌**，统计出可量化的战绩：

- 胜率（信号后 N 日内上涨/达标比例）
- 盈亏比 / 平均 R（按 TY 区间止损口径计算）
- 最大回撤、信号数量、S/A/B 分级表现
- normal（6条件已突破）与 prebreak（5条件预突破）两种模式的分别战绩

**决策价值**：回测结果是参数调优、模式取舍（normal 还是 prebreak 值得挂单）、评级权重（S/A/B 是否分层有效）的**事实依据**；也是向老板解释"为什么信任这套策略"的量化证据。

---

## 二、功能需求

### 2.1 总述

新增 `python main.py backtest` 子命令：**指定历史区间 → 逐股逐日跑策略 V2 评级 → 记录信号 → 跟踪信号后走势 → 输出统计报告**。

### 2.2 输入参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `--start` / `--end` | 回测区间（YYYYMMDD） | 默认近 3 年（数据层上限） |
| `--strategy` | 仅支持 `zuanqian_strategy`（唯一主策略） | zuanqian_strategy |
| `--mode` | `normal`（6条件）/ `prebreak`（5条件） | normal |
| `--interval` | 信号扫描步长（如每日/每 5 日），控制计算量 | 每 5 交易日 |
| `--hold` | 观察窗：信号后 N 个交易日跟踪涨跌（可多值，如 5/10/20） | 10 |
| `--grade` | 只统计指定评级（S/A/B/全部） | 全部 |

### 2.3 执行流程（口径与现有系统严格对齐）

1. **数据**：复用 `data/fetcher.get_daily_kline` + CSV 缓存（`data/cache/`，5202 只 A 股，单只 ≤800 根 ≈ 3 年）。回测区间必须在缓存覆盖范围内。
2. **滚动评分**：对每只股票、每个信号日 T，取**截至 T 的行情窗口**（≥250 根，保证 DL 120 根结构 + 过高点重置有余量），调用 `ZuanQianStrategy.grade()`（normal）或 `prebreak_grade()`（prebreak）得评级与六条件分数。
   - 六条件口径严格复用策略代码：DL（120/90/60 根结构 ± 0.20/0.30/0.35）、PT（≥3/2/2 次平台测试）、LK（紧凑度+像素感+横盘感加权，0.50/0.40/0.30）、TY（5/4/4 根统一区间 ± 3%/5%/8%，3 根=不足 C）、DN（1/2/3 根合并量比 2.5/1.5/1.1 + 实体比 5%/4%/3%）、SF（1st/2nd/3rd 释放级别）、Tier0 一票否决（<60 根/完全释放>40%/通道上涨/无回踩直接冲）。
   - **不重写任何评分逻辑**，只做"时间切片 + 调用"，确保与现行扫描同源。
3. **信号记录**：评级 S/A/B 记为一笔信号，落盘 `output/backtest/<区间>/signals.csv`：股票、信号日、评级、六条件单项分、信号日收盘价、（prebreak）触发价/止损价/风险值。
4. **走势跟踪**：对每笔信号统计信号日后 N 日内的**最高价、最低价、收盘价**，计算：
   - 最大浮盈 / 最大浮亏（相对信号日收盘价）
   - 达标判定（normal）：N 日内最高涨幅 ≥ 阈值（如 5%）记为"胜"；破止损（按 TY 下沿或固定 −8%）记为"负"
   - R 值（prebreak）：(触发价至观察期末) / 每股风险，对齐现有 `risk_per_share` 口径
5. **统计报告**：`output/backtest/<区间>/report.md` + CSV：
   - 总信号数、胜率、平均 R / 盈亏比、最大回撤（组合口径）
   - **S/A/B 分级分列统计**（验证"评级越高战绩越好"的核心假设）
   - normal vs prebreak 对比段
   - 月度分布（信号集中度）

### 2.4 关键实现纪律

- **无前视偏差**：一切指标只在 T 点截断的数据窗口内计算（现有 indicators 均为窗口内计算，天然满足；回测代码必须坚持"先截断、后算指标、再评级"的顺序）。
- **与现有管线复用**：不新增数据源、不复制策略逻辑；回测报告存入 `output/backtest/`，与 `output/scan/` 并列。

## 三、验收草案（5 条可测标准）

1. **命令可用**：`python main.py backtest --start 20240101 --end 20240630 --mode normal --interval 5` 完整跑通，产出 signals.csv 与 report.md，无报错、无空跑警告。
2. **信号口径一致（同源验证）**：随机抽 20 只股票 × 3 个历史信号日，取各自 T 点前窗口，用现有 `diagnose` 路径（同策略、同窗口）比对评级，**S/A/B/C 一致率 100%**——证明回测用的是现行策略，不是另写的一套。
3. **统计指标齐全**：报告含 胜率 / 平均 R（或盈亏比）/ 最大回撤 / 信号数 / S/A/B 分列 / normal 与 prebreak 对比，缺一不可；观察窗 5/10/20 可配置且结果随窗长单调合理（窗口越长，累计收益与风险同时放大）。
4. **无前视偏差抽查**：随机抽 10 笔信号，其"信号日收盘价"与 `data/cache/` 中该股该日收盘价**逐笔一致**（防止时间切片错位）；回测统计中，信号日之后的数据不得出现在该信号的指标计算里（代码审查确认截断顺序）。
5. **可复现**：同一区间同一参数连续跑两次，signals.csv 与 report.md 逐字段一致（输出含策略参数快照与运行时间戳）。

## 四、风险提示（3 条）

1. **过拟合风险**：回测只能证明"过去灵"，不保证未来。最大的陷阱是拿回测结果反复微调阈值（DL/PT/TY/DN 参数）直到好看——那是拟合历史噪音。**对策**：与现有规则对齐——任何量化参数调整必须经老板书面同意（见 `交易部/CLAUDE.md` 量化策略规则），回测只做验证、不做寻优；首期回测结论只读、不联动改参。
2. **幸存者偏差**：股票池是"当前存活"的 5202 只 A 股，退市股、ST 退市股不在池内，回测胜率会**系统性高估**（当年暴雷退市的标的没参加考试）。**对策**：报告中明示样本口径；结论只用于相对比较（S vs A vs B、normal vs prebreak），不做绝对胜率承诺。
3. **数据质量风险**：① 三数据源复权不一致——pytdx 不复权（除权日跳空）、baostock/akshare 前复权，长期窗口价格可能失真；② pytdx 单次上限 800 根 ≈ 3 年，回测区间天然受限；③ 换手率在 pytdx 下恒为 0（已知局限，DN 量比不受影响）；④ 第一版按"信号日收盘价成交"简化，未模拟涨跌停无法买入/滑点，胜率偏乐观。**对策**：报告附数据源与复权说明；深历史（>3 年）回测列为二期（需扩充数据层，另行立项）。

## 五、约束

**时间/优先级**：一期先交付"近 3 年缓存内回测"（数据零成本，直接可用）；二期（历史深回测 5–10 年、复权统一）待数据层扩充后另行立项。不设具体工期，按框架流程排期。

**范围**：
- 仅回测唯一主策略 `zuanqian_strategy`，不做多策略对比、不接 demo 策略；
- 仅验证，**不改策略、不改参数、不改数据**——回测是"考试"，不是"改卷子"；
- 输出口径与现行 scan/diagnose 完全同源（复用同一评分函数）。

**明确不做（一期）**：
- 不做自动参数寻优 / 遗传算法等优化器；
- 不引入外部回测框架（backtrader/vectorbt 等），保持零新依赖、复用现有 indicator 体系；
- 不模拟盘中成交、滑点、涨跌停限制（信号日收盘价成交简化）；
- 不做分钟级 / 盘中回测（仅日线）。

## 六、配套候选（观察池自动登记脚本）

**一句话**：写一个 `python main.py watch-register` 脚本，把每次 scan（及未来 backtest）产出的 S/A/B 信号自动登记进观察池 CSV（含评级、触发价、止损价、登记日），供每日自动跟踪"信号后 N 日涨跌"，与回测形成闭环——**回测验证历史、观察池验证未来**，两者口径一致后，策略战绩就既有历史背书又有实时检验。
