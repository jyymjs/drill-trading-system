## 二、落库 schema（duckdb 三表，PK 幂等 upsert）

```sql
-- 公告表：PK (symbol, date, title)
CREATE TABLE announcements (
    symbol VARCHAR, date DATE, title VARCHAR, ann_type VARCHAR,
    url VARCHAR, adjunct_url VARCHAR, adj_size DOUBLE, org_id VARCHAR,
    fetched_at TIMESTAMP DEFAULT current_timestamp,
    PRIMARY KEY (symbol, date, title));

-- 预约披露表：PK (symbol, report_period) —— 财报日避让核心数据
CREATE TABLE prbook (
    symbol VARCHAR, secname VARCHAR, report_period DATE,
    first_appoint DATE, change1 DATE, change2 DATE, change3 DATE, actual_date DATE,
    fetched_at TIMESTAMP DEFAULT current_timestamp,
    PRIMARY KEY (symbol, report_period));

-- 快讯表：PK (ts, title, source)（source 预留东财 7×24 备用源）
CREATE TABLE news_flash (
    ts TIMESTAMP, title VARCHAR, content VARCHAR,
    level VARCHAR DEFAULT 'normal', source VARCHAR,
    fetched_at TIMESTAMP DEFAULT current_timestamp,
    PRIMARY KEY (ts, title, source));
```

- 幂等：`INSERT OR REPLACE`（与 P3 store 一致），重复拉取不产生重复行；实测重复拉取 3 只后总行数不变（594 → 594）
- 巨潮公告返回中同一 PK 会重复出现（如同一标题多份附件），落库自动去重——属预期行为
- 预约披露字段：`first_appoint` 首次预约 / `change1-3` 变更 / `actual_date` 实际披露（未披露为空）
- 空字符串（接口表示"无"）落库时转 NULL，避免 DATE 列转换失败

## 四、财报日避让怎么用（验收标准 2）

**数据基础**：`prbook.first_appoint`（首次预约披露日）+ 变更字段（change1-3，改期跟踪）+ `actual_date`（实际披露）。

**用法**（`store.next_prbook_dates(con, symbols)` 已内置）：
```python
from 数据基础.duckdb.data_sources import store as DS
con = DS.open_db()                      # 主库
for r in DS.next_prbook_dates(con, ["000651", "600519"]):
    print(r["symbol"], r["secname"], "预约披露", r["first_appoint"])   # 尚未披露
```
- 买入前：查目标股 `first_appoint`，临近（如 T-3 天内）即避让——财报披露前后波动风险
- 披露后：`actual_date` 非空 → 该报告期不再避让；期间改期看 `change1-3`
- **前置条件**：`prbook` 需按报告期刷新。`update.py --prbook` 默认全市场刷新当前报告期（分页翻完 ≈5540 只，约 3 分钟）；报告期由 `default_section_time()` 按当前日期自动推算（如 2026-08 → 2026-06-30 中报期）
