# R-054 止损保护体系落地方案（2026-08-11）

## 一、问题

老板追问止损规则（1R 平保/跟踪止损）——实证 600833 盈利 3.57R，止损云单仍挂原始结构位 9.64。**规则三层脱节：知识库完整、回测半成品、实盘执行零落地**。

## 二、代码现状（探索实证）

1. **exit_manager.py 已实现完整四层面**（evaluate_exit：层面2 1R 平保 R≥1.0→进场价 / 层面3 移动获利 check_trailing_stop（三要素，新止损=拐点低点−回撤10%，须>进场价）/ 层面4 TTP check_36pct_trail（≥5R 且无移动获利点，最高点回落36%）/ 主动出场 detect_active_exit / 分批建议（≥5R full/<5R half））——**代码已有，未接线**
2. **模拟线断线**（sim_trading.py:641）：stop_update 只打印不写回账本，跨日止损上移全丢——实际执行 = 原始止损
3. **执行卡断线**：持仓卡无动态止损指令行——老板每天看不到止损该移到哪，云单静态挂原始价
4. **回测断线**：引擎只有 C5 简化版（低点×0.99）——对照实验已证无效（−79.6R/误伤 83.9%，归档报告），默认关；**精细版（exit_manager 三要素）未回测验证**

## 三、方案

### A. 执行层落地（立即）

**A1 模拟线止损持久化**（bug 修复级）：sim_check 中 verdict["stop_update"] 非空 → 写回 journal 行 stop_loss（跨日持久；entry_price/risk 列不动，R 基准不变）

**A2 执行卡动态止损指令行**：position_card 每笔新增 `📋 止损指令：现止损 X → 建议 Y（依据：1R 平保/移动获利/TTP）`——数据源复用 exit_manager.evaluate_exit（不复制逻辑）；老板每日照卡改云单

### B. 精细版移动获利回测验证（决定自动接入）

- 对照脚本（复用 c5_trail_compare 框架 + exit_manager.evaluate_exit 逐日评估）：基线信号集 20d 触发笔 → 触发日进 → hold 窗口逐日 evaluate_exit（should_exit 出场/stop_update 跟止损）→ 窗口末收盘 → R vs 基线 r_20d
- 判定（沿用 c5 规则）：累计 R 净变化 >0 且误伤 ≤50% → 接入；否则移动获利仅提示
- C5 简化版确认不上线（已有铁证）

## 四、影响面

- 实盘：执行卡每日给出止损建议，老板改云单（券商手动限制）

- 已持仓：600833 明天卖出后无影响；603970/600315 等新规则展示
