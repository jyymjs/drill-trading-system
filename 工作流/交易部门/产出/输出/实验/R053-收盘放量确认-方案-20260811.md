# R-053 执行链补"收盘站稳 + 放量确认"方案（2026-08-11）

## 一、问题（老板质疑 + 实证）

1. 策略合格条件 = "突破阻力线（触发价）+ 放大量"，但执行链只有纯价格条件单（券商云单 ≥触发价 即成交），放量无人把关。
2. 实证：600315 上海家化 2026-08-11 盘中最高 18.50 触发 18.33 成交（100 股），**当日收盘 17.91 跌回触发价下方**（买在假突破）；突破日量比 = 99183/前20日均量 77371 = **1.28 < 1.5（dn_confirm 口径不达标）**。
3. 对照：600833（突破日量比 2.75 ✅）、603970（1.87 ✅）——放量突破，无争议。

## 二、条件单定价标准（现状，代码事实）

- 触发价 = TY 统一区间上沿 × 1.002；止损 = TY 下沿 × 0.998（zuanqian_strategy.prebreak_grade）
- TY 上沿 = 最近 20 根内第一个波幅 ≤5% 的 5/4/3 根平台段最高价
- 触发价低于"突破前某根 K 线最高价"属正常（上影线被波幅过滤排除）——**收盘突破语义**，盘中穿越不算数
- 回测引擎 dn_confirm=1.5：触发日量比 ≤1.5 → 不计入（tracking.py:318）

## 三、执行缺口

| 环节 | 放量把关 |
|---|---|
| 回测引擎 | ✅ dn_confirm=1.5（触发日量比>1.5 才计入） |
| 扫描 | ⚠️ 输出"放量阈值"列，执行卡不展示不校验 |
| 实盘挂单 | ❌ 纯价格条件单（券商功能限制，无法加量/收盘条件） |
| 0.5R 确认三条件 | ❌ 无"突破日放量"确认（③ 仅排除放量阴线） |

**验证**：回测信号集 r43_t2 1,144 笔触发，开仓日量比分布（引擎 qfq 同源口径）——1,143 笔 >1.5（99.9%）；唯一例外 000895 为"信号日在数据截止日"的边界占位触发（引擎 t+1>end 占位记 triggered），非真实缩量突破。**实盘加量比确认与回测不冲突**。

## 四、改动设计（v2 · 2026-08-11 交易部审核意见吸收）

**核心原则（吸收 A-1/A-2）**：indicators 公共层（half_position_confirm_delay2/confirm_conditions）**零改动**——回测引擎（tracking._phase_in_track 同源调用）不受影响；新双条件只在 `sim_trading._check_half_position` 调用侧附加，**恒绑定触发日 entry_idx 定位的数据**（不随 delay2 二判切片漂移）。

1. **挂单指引加量比标注**（scanner 新增"当前量比"列 + execution_card.order_card 展示）：候选行显示 `当前量比 X.X | 放量阈值 Y 手（突破日量比需>1.5）`——老板挂单时可见量能状态；标注语义注明"挂单日量比仅参考，最终以触发日收盘后确认判定"（防误读，吸收 C-1）
2. **0.5R 确认补双条件**（只改 sim_trading._check_half_position 调用侧）：
   - **A 收盘站稳**：触发日收盘 ≥ 触发价（触发日 = entry_idx 定位的开仓日，二判沿用同一数据）
   - **B 放量**：触发日量比 > 1.5（分母 = 触发日前 20 日均量，**不含触发日**，与 tracking.py:316 逐位一致，吸收 B-1）
   - 任一不达标 → 确认失败 → 0.5R 平仓；返回值扩展携带 open_vol_ratio/open_close_ok/reasons 明细（position_card 只展示不复制，吸收 C-2）
3. **持仓卡显示判定**：`收盘站稳✅/❌ 放量 2.75✅/1.28❌`（数据来自 _check_half_position 返回值）
4. **600315 现状**（吸收 B-2 时序）：08-12 首判（A/B 绑定触发日 08-11 → 双不达标 → reject）→ 按 delay2 机制 **08-13 二判仍不达标 → 08-13 收盘平仓**；08-12 执行卡显示 ⏳ wait（不会 08-12 直接平）
