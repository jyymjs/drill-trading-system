## 一、背景与目的

实盘资金 8,401 元下多笔试探仓可能耗尽资金（现状 2 笔持仓 + 今日 3 只新候选，全流程极端需 13,504 元 > 8,401）。老板提议规则："**补仓日钱不够 → 维持 0.5R 不补**"。需回测验证该规则对最终收益的影响，数据支撑老板拍板。

**核心差异**：
- **现状引擎（A）**：pending 预留制——开新仓时冻结所有未确认试探仓的待补款（avail = balance − pending）→ 补仓款本金恒足，但开仓受限（资金不足拒绝，错过机会）
- **实盘现实（B）**：无预留——挂单多 → 触发多 → 确认日可能没钱补仓

## 二、已探明代码事实（供审核核对）

| 项 | 位置（sim_capital.py） | 现状行为 |
|---|---|---|
| pending 预留 | L337-340 | pending = Σ未settle的half_ok持仓add_cost；avail = balance − pending；只冻结 add_cost，fee_add 未冻结（理论小额负值） |
| 确认日补款 | L288-298 | 无条件扣款 balance −= add_cost + fee_add；**无余额不足检查**、无拒绝、无计数；持仓照常翻倍 |
| 开仓被拒 | L350-359 | avail 不够 → reasons["资金不足"]；风险预算不够 → 动态键"每股风险{值}超限" |
| 参数透传链 | sim_capital 签名 L117-128 → r44.run_one L57-62/L83-87 → r48.run_cell L187-197（cell 清洗 L403-405） | 新参数默认 False 则全部调用方零变化 |
| 测试现状 | test_half_phase_capital.py::test_pending_reserve_blocks_other_open | 只覆盖"预留阻止新开仓"（A 行为）；**无"确认日余额不足补款"测试** |

## 三、测试设计（对比矩阵 8 格）

| 格 | 配置 | 用途 |
|---|---|---|
| A26 | 8401×0.025×999 × 26 年（现状预留） | 基线（对账：应 = +1534%/-13.8%，R-050 主网格已有） |
| B26 | 同上 × confirm_shortfall_skip=True | 核心：缺钱不补 26 年影响 |
| A7y / B7y | 同上 × 近 7 年（min_date=2019） | 近 7 年口径 |
| Ainj / Binj | 8401×0.025 × 近 3 年 + 月注入 3000×risk_growth | 实盘注入路径（确认日资金更紧） |
| A30k / B30k | 30k×0.025 × 26 年 | 资金充足对照（差异应小） |

**指标**：收益%/回撤/成交笔数/**补仓失败笔数（B 特有，reasons["补仓资金不足"]）**/补仓失败笔 avgR（半仓 R）/开仓"资金不足"拒绝数（A 有 B 无——B 取消预留后拒绝应减少）。

**判定**：B 相对 A 的收益差（pp）→ 老板拍板：①"钱不够不补"规则是否采纳 ② 若采纳，执行卡加"挂单资金占用校验"（挂单前自动算总账）。

## 四、实现（引擎改动，默认零变化）

1. **sim_capital.py**：
   - 签名加 `confirm_shortfall_skip: bool = False`
   - 开仓 L337-340：True 时 `pending = 0`（不预留——模拟实盘无预留）
   - 补款循环 L288-298：True 且 `balance < add_cost + fee_add` → `half_settled=True` 但不翻倍（shares/risk_actual 维持半仓）+ `reasons["补仓资金不足"] += 1` + 该笔 `half_shortfall=True`（金额减半但 R 不变，可归因）
   - 返回 dict 加 `n_confirm_shortfall`
2. **r44.run_one** 透传 `confirm_shortfall_skip=False`（默认零变化）
3. **r48.run_cell** cell 字段清洗加该键（同款 NaN 清洗）
4. **测试**：新增 `test_half_shortfall_skips_confirm`（B 模式：余额不足 → 维持半仓 + 计数 + 无翻倍）；现有测试默认路径不变
