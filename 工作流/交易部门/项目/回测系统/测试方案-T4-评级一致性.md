# T-4 测试方案：代码评级 vs 老师评级一致性

> 补课代码化第一批（2026-08-04 老板拍板：测试驱动，量化是稳定执行器）
> 目标：验证 `zuanqian_strategy.grade()` 的六条件评级与老师实际评级判定的一致性，量化"代码离老师有多远"

## 一、目的

老师评级是视觉判定（S/A/B/C），代码评级是量化规则。本测试用老师实际点评过的案例做校准基准，逐条对比：

- **一致的** → 该条件函数学对了，是稳定执行器
- **不一致的** → 逐条差异分析，定位是哪个条件函数（DL/PT/LK/TY/DN/SF）判偏，驱动后续改进

## 三、测试管道

```
案例基准表（CSV：品种/代码/日期/老师评级）→ 数据获取（缓存优先，akshare 兜底）
→ zuanqian_strategy.grade(df) → 代码评级
→ 对比（老师判定 vs 代码判定 + 六条件逐条）→ 一致性报告 + 差异分析
```

- 数据：`数据基础/数据/cache`（A股 5232 缓存）；期货/美股走 fetcher 三路（akshare 兜底）
- 日期：以案例日期为行情终点，取前 120+ 根日线
- 判定映射：老师"关注/做" ↔ 代码 S/A/B；老师"不关注/pass/不符合" ↔ 代码 C/Tier0 否决

## 四、验收标准

| 指标 | 首轮目标 |
|---|---|
| 总体一致性率 | ≥70%（方向参考） |
| 六条件逐条 | 输出每个条件函数的判对率，定位主要分歧源 |
| 差异分析 | 每个不一致案例给出"代码判了什么/老师判了什么/可能原因" |

## 五、产出

1. `output/backtest/t4_rating_consistency/` 一致性报告（逐案例 + 汇总）
2. 评级函数差距清单（哪些条件需要按老师口径调参 → 后续 T 系列候选）

## 六、红线

- 本测试只读案例 + 写测试脚本与报告，**不改主策略参数**（量化参数铁律：调参需用户书面同意）
- 测试发现需调参的条目 → 列出修改建议 → 用户确认 → 走流程
