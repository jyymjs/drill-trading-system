## 背景与定位（用户明确）

**系统定位**：学习部**仅为一个大的系统框架**——为「所有新知识」提供学习流程的项目（B站/论文/博客抓取 → 入库 → 总结/对抗 → 可调用产出）。它**足够通用**，学习内容能被**任何项目调用**。

**核心诉求（用户原话提炼）**：
- 学习结果存进资料库，**按分类整理放好**（方便模型调用）
- **如何分类由模型（AI）判断**，用户不指定
- **文件名一定要有相关性**——否则后续调用资料得把全部内容看一遍，没用的也被输入，浪费 token
- 用户提出**大的需求时，框架自动启动本系统 agent 辅助规划者**
- 用户也**可以只使用学习部**学习，不调用工程中枢执行任务

## 一、知识库架构（v1.3 定案）

**方案：全局共享库（deepseek/知识库/）**
- 学习产出全部存 `deepseek/知识库/`，**任何项目**通过统一路径调用
- 学习部本身自包含（CLAUDE.md/agents/skills/scripts），数据在全局库
- 依据：系统定位是「为所有新知识提供流程」的框架，产出是「任何项目可调用」的资产——数据归全局，流程归系统

**多级嵌套（v1.3）**：
- 分类由 AI 判定，**允许多级嵌套**：`知识库/交易系统/出场体系/`——相关性优先，可深目录
- 防止「系统能访问但人难找」：嵌套按相关性展开，无相关性的不硬套

**系统文件独立目录（v1.3）**：
- `知识库/系统/`：提示词模板、命令、流程定义等系统文件**单独存放**，不和学习资料混淆
- 资料一律不进系统目录，系统文件一律不进主题目录

**资料分层（v1.3，用户咨询定案）**：
- **raw/ 原始层**：爬下来的原文（字幕全文/论文原文），存 `知识库/{主题}/raw/`——保真、可溯源、可重新提炼
- **精炼层**：AI 拆解/学习笔记/方法建议书——**日常调用层**，模型默认只读这层
- **索引只列精炼层**：index.md 不含 raw 文件；raw 按需进入（文件名精准命中，不读全文）——省 token 的核心机制
- raw 保留成本≈0（KB 级文本）；质量差的 raw（乱码/无价值）可删

**分类机制（AI 自动判断）**：
- 学习时由 AI 分析内容自动判定主题路径（可多级），存入对应目录
- 主题命名保持全库一致（新主题先查 index，避免近似名重复建目录）

**文件名相关性规范（省 token 核心机制）**：
- 所有精炼层产出文件名由 AI 生成，格式：`{日期}-{主题}-{内容要点}-{类型}.md`
  - 笔记：`2026-08-01-交易系统-出场六层体系-学习笔记.md`
  - 建议书：`2026-08-01-AI学习方法-学习闭环-方法建议书.md`
- 内容要点 ≤8 字，让**只看文件名就能判断相关性**，实现按需精准加载
- 文件头含元数据块（标题/主题/来源/日期/关键词/时效性），检索时 grep 文件名+头部即可命中，不读全文
- raw 层文件名：`{来源简写}-{BV号或链接名}-{日期}.md`（raw 不参与相关性索引，按来源追溯）

## 优化项（v1.4，全部采纳）

**O1 主题知识卡（碎片合并，防臃肿核心）**：
- 同一主题碎片笔记攒到阈值（如 ≥5 篇）→ 合并成一张「主题知识卡」（该主题完整知识结构）
- 模型调用主题时**只读知识卡**；碎片文件保留在 `{主题}/archive/` 或 `{主题}/碎片/`，按需进入
- 知识卡文件名：`{主题}-知识卡.md`（如 `交易系统-知识卡.md`），头部含更新日期与版本

**O2 通用网页/论文抓取器（补齐来源）**：
- 实测硬伤：WebFetch 对 arxiv.org / huggingface.co 等学术域名受限抓不了
- 新增脚本能力：任意 URL → 正文提取 → 按同一规范入库（标题/作者/发布时间/正文）
- 学术来源（论文）优先走脚本抓取，WebFetch 只做补充

**O3 SESSDATA 过期检测**：
- 抓取时检测登录态失效（nav 接口 isLogin=False）→ 明确提示「SESSDATA 已过期，请更新 config.local.json」，不静默降级

**O4 知识库调用协议（省 token 制度化）**：
- `知识库/系统/调用协议.md`：统一规定调用路径「① index（找主题）→ ② 主题 index（找文件）→ ③ 文件名+头部元数据（判相关性）→ ④ 正文（才读取）」四级检索
- 模型与人调用一律按协议执行，不靠自觉

**O5 主题级索引**：
- 主题下文件 >8 个 → 自动生成该主题局部 index.md；全局 index 只留主题入口行
- 两级索引：全局（主题列表，短）+ 局部（文件列表，短）

**O6 执行知识回流（知识闭环）**：
- 框架执行任务中产生的新知识（执行者发现的技术要点、审查者结论、优化者模式洞察）→ 按规范回流知识库 `{主题}/`（精炼层，AI 分类+命名）
- 形成「学习 → 应用 → 新知识 → 再入库」闭环；回流入口：工程中枢执行流程（执行者交付时可选提交「知识产出」）

**O7 时效性标注**：
- 元数据加 `时效性: 长期/中期/短期`（如市场扫描类短期、交易规则类长期）；AI 判定
- 调用时按需过滤（如学习 2026 年内容时排除 2024 短期项）

**O8 产出模板化**：
- `知识库/系统/templates/`：学习笔记/方法建议书/知识卡/raw 档案的结构模板
- 所有产出按模板生成，格式统一，模型调用时可快速定位章节

## 二、双模式（保持不变）

- **模式 A 知识总结**：直接丢链接「总结这个」→ 抓取 → 结构化学习笔记
- **模式 B 规划前置**：给需求「先学习再规划」→ 多源学习 → 双 agent 对抗 → 方法建议书
- 抓取链路已实测（登录态 WBI 签名 + 明文 URL 直连，秒级；信息/字幕/弹幕/评论）

## 三、框架自动启动（已确认：规划者自主判断）

规划者接手需求时自动判断：① 新领域/方法不确定 ② 任务复杂度高 ③ 用户主动要求——任一为是 → 自动启动学习部（模式 B）出《方法建议书》→ 再进入拷问规划。规划确认书引用建议书路径。

## 四、独立使用（用户可在系统内学习）

在 `deepseek/学习部/` 目录直接对话（该目录 CLAUDE.md 定义学习 agent 行为），仅使用学习流程，不触发框架执行任务。
