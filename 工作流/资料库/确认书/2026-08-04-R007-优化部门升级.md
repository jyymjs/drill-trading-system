## 一、背景(为什么做)

内审部原为工程部门下第 4 角色,每 5 任务醒来做周期审计。老板观察到:

1. **内审存在感弱**——系统问题散落各处(路径过时、老名残留、口径不一致),没有统一收口,很多问题老板根本不知道
2. **缺少升级动力**——框架主要靠老板主动提需求才变,缺少一个持续推动系统更新升级的引擎

决定:**内审部升级为与工程部门平级的一级部门"优化部门"**,职能从"审计"扩展为"稳定 + 告知 + 动力"。

## 二、决策(老板已拍板)

1. **独立一级部门**:新建 `工作流/优化部门/`,与工程部门平级,原内审文件迁入
2. **分级告知**:紧急问题立即说 / 普通问题任务收尾汇总 / 长期问题进台账周报
3. **行动边界**:低风险(错别字/格式/文档口径)直接修+告知;高风险(规则/角色/技能/脚本)提案等老板确认才动

## 三、新职能(三大职责)

### 1. 维持系统稳定(保留审计职能)
- 沿用七维审计(审规则/审技能/审角色/审一致/漏洞复盘/规划部反馈/自动回顾),周期触发保留:`/优化` 手动 + 冷却期自动
- 深度检查时派出子 agent(原内审部做法);日常由主对话巡检

### 2. 问题收口(新增,核心)
- **所有任务过程中发现的问题,统一登记到 `优化部门/问题台账.md`**——来源:规划部拷问中发现、工程部施工中暴露、质检退回、日常对话发现(如路径过时/文档错误/口径残留)
- 台账字段:问题 | 来源 | 级别(紧急/普通/长期)| 状态(登记/处理中/已闭环)| 处理方式
- 每笔登记留痕,闭环打勾,可追溯

### 3. 分级告知 + 升级动力(新增)
- **紧急**(影响当前任务/数据安全/规则被破坏):立即告知老板
- **普通**(口径/过时/格式):任务收尾时汇总一条
- **长期**(潜在优化方向/重复模式):进周报,供老板决策
- 对台账问题给出处理建议:低风险直接修+登记;高风险提案 → 老板确认 → 工程部施工;升级建议沉淀 changelog

### 4. 主动优化建议(新增 · v1.1)
- 不只是"发现问题",还要**附药方**:台账每笔问题登记时同步给出优化建议(怎么改/更优做法/可选方案)
- **主动提出改进方向**:不限于已发生的问题——发现重复模式(同类问题≥2 次)建议沉淀成规则/技能;发现架构可优化处,提出改进方向供老板决策
- 定期输出**优化建议清单**(随周报/深度审计),老板可批量拍板

## 四、组织变化

- **新建 `工作流/优化部门/`**:CLAUDE.md(定位)+ 问题台账.md(收口+分级+状态)+ 审计流程(原 optimizer.md 迁入改造)
- **工程部门**:四角色减为三(规划/执行/测试),`流程/内审/optimizer.md` 迁出,内审条目全移除
- **同步更新**:组织架构.md、根导航表、工程部门/CLAUDE.md、工程部门/README.md、settings.json(hook 提示词)
- **联动处理**:老名修正待办中涉及"优化者"的部分(settings.json hook、task-counter.sh、regression-log.md)随本次一并完成

## 五、边界(不做的事)

- 不动质检部(六轴验收)与签字机制
- 不动提案机制(全员提案→主对话审核);关系:**台账=问题池,提案=改动方案**,台账问题要动手时走提案
- 交易部/学习部/公共资源部不涉及
- 历史文件(changelog 旧条目、已归档确认书)不改

## 六、验收标准

1. `工作流/优化部门/` 存在:CLAUDE.md + 问题台账.md + 审计流程
2. 工程部门无"内审/优化者"残留(目录/文档/组织架构/hook)
3. 触发可用:`/优化` 唤醒 + 冷却期自动
4. 问题台账具备分级规则,各部门问题可登记,**每笔问题附优化建议**
5. 台账首条已有实际内容(今天发现的遗留问题登记进台账,含老名修正 7 处)
6. 台账问题中已有可沉淀的改进方向(如重复模式→规则建议)输出样例

## 七、施工安排

- 施工方:工程部(子 agent 或主对话,文档+目录迁移,低风险)
- 流程:老板确认 → 施工 → 质检六轴验收 → 老板签字 → 确认书归档
