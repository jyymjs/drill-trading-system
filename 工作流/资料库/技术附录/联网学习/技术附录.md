## 一、B 站爬虫脚本（实测链路，全部秒级）

位置：`scripts/bilibili/fetch.py`。纯 Python：requests + bs4（环境已验证）。SESSDATA 读 `scripts/bilibili/config.local.json`（已存在，已入 .gitignore）。

### 实测通过的接口链路

1. **视频信息**（游客即可）：`https://api.bilibili.com/x/web-interface/view?bvid={bvid}`
   - 返回 title/desc/owner/cid/aid/pubdate。aid、cid 为后续接口所需。

2. **字幕列表**（需登录态）：`https://api.bilibili.com/x/player/wbi/v2?bvid={bvid}&cid={cid}`
   - **必须带 SESSDATA cookie**（`s.cookies.set("SESSDATA", ..., domain=".bilibili.com")`）
   - **必须 WBI 签名**：img_key/sub_key 从 `x/web-interface/nav` 获取，mixinKeyEncTab 常量表（见下），参数排序 + wts + md5 得 w_rid
   - 返回 `data.subtitle.subtitles[]`：**取 `subtitle_url` 字段（明文）**，不要用 subtitle_url_v2（加密版）
   - 字幕项含 lan（ai-zh 等）、lan_doc（中文）
   - ⚠️ 无字幕视频：subtitles 为空数组，直接提示「无字幕」而非报错

3. **字幕下载**（无需 cookie）：直连 `subtitle_url`（`https:` + 相对路径），返回 JSON：`{"body": [{"from":..,"to":..,"content":"..."}, ...]}`
   - auth_key 为签名凭证，有效期有限（毫秒级时间戳），**不要缓存字幕 URL，每次现取**

4. **弹幕**（游客即可）：`https://api.bilibili.com/x/v1/dm/list.so?oid={cid}` → XML `<d p="...">内容</d>`
   - p 属性第 5 段为热度，可筛 TOP-N 弹幕

5. **评论**（游客即可）：`https://api.bilibili.com/x/v2/reply?type=1&oid={aid}&sort=2` → 按热度评论

### WBI 签名常量（实测可用）

```python
MIXIN_TAB = [46,47,18,2,53,8,23,32,15,50,10,31,58,3,45,35,27,43,5,49,33,9,42,19,29,28,14,39,12,38,41,13,37,48,7,16,24,55,40,61,26,17,0,1,60,51,30,4,22,25,54,21,56,59,6,63,57,62,11,36,20,34,44,52]
# mixin_key = 从 nav 的 img_url/sub_url 文件名（去扩展名）拼接后按 MIXIN_TAB 取前32字符
# 签名: params + wts=time → 排序拼接 → md5(拼接+mixin_key) → w_rid
```

### 风控保护（必须实现）
- 完整浏览器 UA + Referer: `https://www.bilibili.com/`
- 视频间请求间隔 ≥2 秒；批量模式支持 `--sleep` 参数
- 遇风控码（-412 / -403 / 412）立即停止并输出明确错误，**不重试轰炸**
- SESSDATA 只用于读取，绝不调用写接口
- 读 config.local.json 失败或无 SESSDATA → 降级为游客模式（仅信息+弹幕+评论），字幕输出「需登录」

### 输入
- `--url` / `--bvid`：单个视频；`--list`：链接文件；自动提取 URL 中的 BV 号
- `--no-danmaku` / `--no-comment`：可选关弹幕/评论
- 无字幕视频 → 明确提示，不报错

### 输出（知识库规范）
每个视频一个 markdown 档案（见子任务 2 目录规范），文件名 `{bvid}.md`，BV 号做去重键。

## 二、知识库缓存（子任务 2）

- 位置：`docs/knowledge/{主题}/`，每主题 `index.md`
- 档案结构：
  ```markdown
  # {标题}
  元数据: UP主 / 链接 / 日期 / BV号
  ## 简介
  ## 字幕全文
  ## 热门弹幕
  ## 热门评论
  ```
- 去重：爬取前查 index（或检查 `{bvid}.md` 是否存在），命中则跳过
- 用户自贴资料：`docs/knowledge/{主题}/manual-{序号}.md`

## 三、learn 技能主流程（子任务 3）

技能位置：`.claude/skills/learn/SKILL.md`

1. 输入收集：需求 + 用户贴的视频链接/文档
2. 来源定位：WebSearch 找最匹配来源——B 站默认主力（`site:bilibili.com {主题}`）；算法/理论 → arXiv/论文；实操 → 技术博客。产出来源清单 ≤5 条
3. 抓取：B 站走 fetch.py；网页/论文走 WebFetch；用户自贴资料直接入库
4. 入库：按规范写入，更新 index
5. 学习：双 agent 对抗（输入：需求 + 知识库档案）
6. 报告：`docs/reports/{日期}-{需求}-方法建议书.md`

区分 research 技能：research = 规划中后台查证事实；learn = 规划前多源方法学习+对抗提炼。

## 四、双 agent 对抗协议（子任务 4）

Agent 工具派发 2 个 general-purpose 子 agent：
- **提炼者 A**：读全部学习档案 + 需求 → 「可行方法清单」（方法名/来源引用/核心要点/适配度/实施建议）
- **质疑者 B**：逐条质疑（可行性/适配度/盲区/对立观点），每条质疑给依据
- **轮次**：默认 2-3 轮（A 修订 → B 复核 → A 再修订或收敛）。终止条件：无新质疑或达轮数上限
- **输出**：《方法建议书》——采纳（含质疑修订记录）/ 争议（分歧显式保留）/ 否决（+原因）三清单
- 轮数上限为硬性约束防发散

## 五、规划集成（子任务 5）

- `agents/规划.md` 流程第 1 步前插「学习判断」：领域新/方法不确定/用户要求 → 触发 learn
- `planner/SKILL.md` 拷问示例表加一行
