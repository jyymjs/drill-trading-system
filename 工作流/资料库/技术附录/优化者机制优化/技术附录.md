# 技术附录：优化者机制优化

## 1. Stop hook 配置

**文件**：`.claude/settings.json` 新增 `hooks` 字段：

```json
{
  "hooks": {
    "Stop": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "bash scripts/guard/task-counter.sh"
          }
        ]
      }
    ]
  }
}
```

**脚本**：`scripts/guard/task-counter.sh`（新建）

```bash
#!/bin/bash
# task-counter.sh — 优化者唤醒提醒（Stop hook 触发）
# 计数到 5 且冷却期到期 → 输出提醒文本；否则静默退出
COUNT_FILE="docs/.task-count"
LAST_OPT="docs/audit/last-optimization.txt"

[ -f "$COUNT_FILE" ] || exit 0
COUNT=$(cat "$COUNT_FILE")
[ "$COUNT" -ge 5 ] || exit 0

# 冷却期检查：距上次优化 >= 24h（无记录则视为到期）
NOW=$(date +%s)
if [ -f "$LAST_OPT" ]; then
  LAST=$(cat "$LAST_OPT")
  DIFF=$(( (NOW - LAST) / 3600 ))
  [ "$DIFF" -ge 24 ] || exit 0
fi

echo ""
echo "⚠️  优化者待唤醒：任务计数已达 $COUNT/5 且冷却期已过。"
echo "    回复「唤醒优化者」或输入 /优化 启动审计。"
```

**配套改动**：
- `agents/planner.md`：计数动作保留（任务完成 `echo +1`），触发描述改为"计数到 5 + Stop hook 提醒 + 用户确认唤醒"；冷却期检查指向 `docs/audit/last-optimization.txt`
- `agents/optimizer.md`：触发节同步；优化完成后 `date +%s > docs/audit/last-optimization.txt`
- `scripts/guard/validate-harness.sh`：新增两文件检查项（task-counter.sh、last-optimization.txt 约定）

**注意**：hook 每次 Stop 都会跑脚本，脚本必须无副作用、静默退出（exit 0 无输出时 Claude 不显示任何内容）。冷却期时间戳用 Unix epoch 便于比较。

## 3. 冷却期 + 健康分行动绑定

- 时间戳落点：`docs/audit/last-optimization.txt`（存 `date +%s`），planner.md 与 optimizer.md 均引用此路径
- `agents/optimizer.md` 健康分节追加行动列：

| 状态 | 条件 | 行动 |
|------|------|------|
| 🟢 | 退回率<20%、无退化积压 | 正常节奏（5 任务） |
| 🟡 | 退回率 20-50%、有待归档 | 下次审计优先清退化项 |
| 🔴 | 退回率>50%、多次同类错误 | 触发间隔降为 3 任务 + 强制深度审计 |

## 4. 优化提案流程（新功能）

`agents/optimizer.md` 新增"提案确认"节：

```
审计发现问题 →
  高风险（改规则/角色/技能/脚本逻辑）：
    出「优化提案」→ 返回主对话推给用户（文件清单+改动要点+原因+回滚方式）→
    用户确认 → 执行 → 审查者验证 → changelog
  低风险（错别字/归档退化项/格式）：
    直接执行 → changelog 标注"已执行，可回滚"
```

- 提案为会话内文本，不落盘（避免提案垃圾文件）；执行完成后变更记录入 `docs/changelog.md`
- 优化提案被拒 → 标注"已驳回"（现有机制保留）
- 与 R5 一致：确认 = 用户明确同意，沉默不算
