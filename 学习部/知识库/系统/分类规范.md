## 一、目录结构与单库分层

```
知识库/
├── index.md                ← 索引入口（老板知识库索引）
├── 复盘/                    ← 元层（不分库）：资料库复盘报告 + 素材处理台账
├── 系统/                    ← 元层（不分库）：协议/规范/模板，资料一律不进
│   └── templates/          ← 产出模板（学习笔记/主题知识卡/raw档案）
├── 待处理/                  ← 元层：素材中转区（转写稿等待处理素材）
└── 老板知识库/{主题}/        ← 学习产出唯一归属：学习笔记/错题卡/raw
        （主题内含 raw/、archive/、局部 index、知识卡）
```

**铁律**：
- 资料一律不进 `系统/` 目录，系统文件一律不进主题目录
- raw/ 层与精炼层**永不混放**：抓取原文一律进 `{主题}/raw/`，笔记/知识卡/错题卡在主题根
- 索引（全局 + 局部）**只列精炼层**，raw 不列

### 单库分层（2026-08-03 老板拍板：公司资料库废除）

**背景**：原双库（老板知识库 + 公司资料库，培训部双轨制）已废除（2026-08-03 老板拍板）——系统学轨道/入库闸门取消，交易知识归交易部自建知识库（`交易部/知识库/`）。学习部知识库统一为**单库：老板知识库**。

**归位规则（按产出类型）**：

| 产出类型 | 归位 |
|---|---|
| 学习笔记 / 错题卡 | → **老板知识库**（唯一学习产出归属） |
| raw 原文层 | **跟随精炼产出所在库**（老板知识库/{主题}/raw/） |
| 系统/（协议/规范/模板）、复盘/（体检报告/台账）、待处理/（素材中转） | **不分库**（元层） |

- 每个产出文件头部元数据必带「库归属: 老板知识库」字段（见「四、元数据块」）

**跨库查重**：
- 新产出入库前**先查两库索引**（index.md 双入口）：同主题跨库已有产出 → 按「九、知识接入」判定关系（互补/升级/冲突/重复）并跨库互链
- 两库并存同名主题**不是重复主题**——各自按产出类型归位，查重时须同时核对两库，不得因跨库同名而误判重复或跳过关联
- 检索跨库须显式声明（默认只检本库，见调用协议「定检索面」）

## 二、分类判定规则（AI 执行）

1. **AI 分析内容定主题**：读完内容后判断其知识领域，主题 = 领域名（如 `AI编程`、`AI学习方法`、`交易系统`、`量化`）
2. **允许嵌套**：相关性需要时用多级路径 `知识库/交易系统/出场体系/`，按相关性展开，无相关性的不硬套
3. **新主题先查 index**：建新主题前先查全局 index，**避免近似名重复建目录**（如已有 `AI学习方法` 就不再建 `AI学习`）；主题命名全库一致
4. **无主题归属**：暂时无法归类的内容可暂存 `知识库/未分类/`，后续学习时归并
5. **判定质量责任**：分类错误由后续学习/回流/复盘时修正（改目录 + 更新索引，保持索引与文件一致）

## 三、文件名规范（省 token 核心机制）

- **精炼层**：`{日期}-{主题}-{内容要点}-{类型}.md`
  - 日期 `YYYY-MM-DD`；内容要点 ≤8 字；类型 ∈ {学习笔记, 方法建议书}
  - 例：`2026-08-01-AI学习方法-学习闭环-方法建议书.md`
  - 目标：**只看文件名就能判断相关性**，实现按需精准加载
- **raw 层**：`{来源简写}-{BV号或链接名}-{内容}-{日期}.md`
  - 来源简写：B站 / 论文 / 博客 / 网页 / manual（用户自贴资料）/ 书籍（拆书分卷）
  - 例：`B站-BV1wMduBNEPS-Agent学习路线-20260801.md`
  - raw 不参与相关性索引，按来源追溯
- **主题知识卡**：`{主题}-知识卡.md`（如 `交易系统-知识卡.md`），头部含更新日期、版本号与关联主题
- **错题卡**：`错题卡.md`（主题根，每主题一张）
- **复盘报告**：`知识库/复盘/{日期}-资料库复盘-复盘报告.md`

## 四、元数据块（每个文件头部必须有，frontmatter 风格）

```yaml
---
标题: <文件标题>
主题: <所属主题路径>
库归属: <老板知识库 | 公司资料库 | 系统 | 复盘>
来源: <链接或出处，含作者/UP主>
日期: <YYYY-MM-DD>
关键词: [<关键词1>, <关键词2>]
时效性: <长期 | 中期 | 短期>
可靠性: <一手数据|实证|学术理论|实操经验|自述传闻|待核实>
关联: [<相关主题名> 或 <知识卡相对路径>]
---
```

**库归属（双库标记，R-001 定案）**：
- 每个文件头部必带「库归属」字段，取值与所在目录一致：方法建议书 → `公司资料库`；学习笔记/错题卡 → `老板知识库`；协议/规范/模板 → `系统`；体检报告/素材台账 → `复盘`
- 库归属 = 调用权限与检索面的第一判定依据（权限声明见调用协议）；文件移动时同步更新该字段
- 索引（index.md）按库分入口，翻目录/索引即辨人学轨道/系统学轨道产出

**时效性判定（O7，AI 自行判断）**：
- 短期：市场扫描/工具功能/新闻类（如 B 站工具功能介绍）
- 中期：技术教程/学习路线（API 会变但方法论稳定）
- 长期：方法论/交易规则/学习体系（多年有效）

**可靠性分级（来源质量信号，AI 如实标注）**，从高到低：
1. **一手数据 / 实证**：原始数据、可复现实验、实测记录
2. **学术理论**：同行评审论文、教科书体系
3. **实操经验**：一线从业者/创作者的方法沉淀
4. **自述传闻**：个人转述、未经核实的说法
5. **待核实**：无法判级，需验证后再用

**关联字段（网状结构）**：
- 每条精炼产出必带 `关联:` 字段——填相关主题名或知识卡相对路径（如 `AI学习方法`、`知识库/交易系统/交易系统-知识卡.md`）
- **互链**：A 关联 B，则接入时在 B 侧补上对 A 的关联（跨主题补互链），使树状库长出"边"
- 模型调用该产出后，可循 `关联:` 跳转到相关主题（见调用协议「关联跳转」）

## 五、主题知识卡机制（O1 · 碎片合并防臃肿）

- **触发阈值**：同一主题精炼碎片（笔记等）累计 **≥5 篇** → 合并成一张 `{主题}-知识卡.md`
- 知识卡 = 该主题完整知识结构（见模板），模型调用主题时**只读知识卡**
- 合并后：碎片文件移入 `{主题}/archive/`（保留，按需进入），主题目录只剩知识卡 + raw/ + index
- 知识卡头部：更新日期 + 版本号（v1/v2…）+ 关联主题，每次合并升版
- **认知增量记录**：版本记录节必须写明每次升版"发生了什么"（v1→v2 新增/修正/替换了哪些认知），保证知识演进可追溯
- 后续碎片 <5 时继续写入碎片；达阈值再次合并升版

## 六、主题级索引机制（O5 · 两级索引）

- **触发阈值**：主题下精炼文件（不含 raw、不含知识卡本身）**>8 个** → 生成 `知识库/{主题}/index.md`
- 局部索引内容：主题内精炼文件列表（文件名 + 一句话说明），**短**
- 全局 index 该主题只剩一行入口（指向局部索引）
- 文件数回落 ≤8 时保留局部索引（无害），或删除并回到全局直列

## 七、索引维护规范

- **每次产出后必须更新**：全局 index.md（双索引入口）对应**所属库**的主题行（追加文件条目）
- **新主题**：在所属库的索引入口加一行主题入口；仅 raw 层（暂无精炼产出）的主题也要登记入口行（标注「仅 raw 层」）
- **清理**：删文件后同步删索引对应条目，保持索引与实际文件一致
- 错题卡、复盘报告同样列入全局索引（类型：错题卡 / 复盘报告）
- **跨库关联**：关联字段跨库引用时使用相对知识库根的完整路径（如 `老板知识库/AI学习方法/xxx.md`），保证跨库跳转可达

## 八、错题卡规范（考问模式产物）

- **位置**：`知识库/{主题}/错题卡.md`，按主题分散，每主题一张
- **条目结构**：
  - 题目/知识点：一句话描述没掌握的是什么
  - **推理断点**：重建推理时断在哪一步、卡在哪个环节（AI 记录用户原话或断点描述）
  - **归因**：提炼失真（→ 已修笔记）或 遗忘（→ 复习），二选一
  - 复习计划：第 1 次 / 第 7 次 / 第 30 次（间隔重复，各带日期）
  - 复习记录：每次复习标注 通过/失败（通过 = 用户自己重建推理链成功，AI 只引导不提示）
  - 状态：未掌握 | 已掌握
- **毕业机制（防错题卡无限膨胀）**：三次间隔复习（1/7/30）全部重建通过 → AI 判定已掌握 → 标记"已掌握"并移入 `{主题}/archive/` 归档（不删除，可查）；任一次重建失败 → 停留并重新计间隔
- 错题卡条目由考问模式产生与维护，流程见 [SKILL.md](../../.claude/skills/learn/SKILL.md)「考问模式协议」

## 九、知识接入协议（新知识落地五步）

每批新知识（学习/考问/拆书/复盘产出）入库前按此五步接入，**任何产出不得静默入库**：

```
① 定位：按「二、分类判定」定主题路径；按「双库分层」定所属库
② 对接：按调用协议四级检索，找出同主题全部旧产出（含跨库同主题产出——跨库查重，两库索引都查）
③ 判定关系：新产出与旧产出是 互补 / 升级 / 冲突 / 重复 之一，写明判断依据
④ 落地：按下表动作执行
⑤ 索引：更新所属库的全局 index 入口 / 局部索引 / 知识卡（按「七」）
```

**落地动作**：

| 关系 | 落地动作 |
|------|---------|
| 互补 | 入库 + 与旧产出**关联字段互链**（两边都写） |
| 升级 | 入库 + 旧文件头部标注"已被 YYYY-MM-DD《XX》修正" |
| 冲突 | 双方入库 + 各自头部标注"冲突，适用条件：…" |
| 重复 | **并入既有产出**（不新建文件，内容合并到旧产出或知识卡） |

**网状结构**：所有落地动作都包含关联字段维护（见「四、关联字段」）——知识"接上去"而非"放进去"。

**冲突处理四步**：
1. **识别**：接入时对接 / 复盘时扫描（同主题矛盾并存）
2. **分析**：各自适用条件、时效、依据，判断是伪冲突（条件不同）还是真矛盾
3. **标注双方**：互相标注"冲突，适用条件：…"，双方保留
4. **特殊情形**：
   - 一方明确**过时**（时效性=短期且已失效）→ 标"过时/已被替代"，不删除
   - 一方明确**错误**（发现勘误）→ 标"勘误"+ 修正依据
   - **判定不了** → 双方保留，标"冲突未裁决，待用户裁决"，并写入复盘 NEXT 清单提示用户
   - 过时/勘误条目触发**重学** → 新产出走"升级"关系覆盖（参考核心机制②）

**陈旧规则淘汰**：
- 规则卡（情境→行动）随考问模式按 1/7/30 回顾；被新规则覆盖 → 标注"已被《XX》替代"淘汰（**只标注不删除**）
- 陈旧规则淘汰后，新规则走"升级"关系入库

## 十、回流（O6 · 系统内回流接通）

- 系统内**学习 / 考问 / 拆书 / 复盘**产出的知识，全部按本规范回流知识库：先按「双库分层」定所属库（建议书→公司资料库、笔记/错题卡→老板知识库、元层→系统/复盘），再 AI 分类 + 相关性命名 + 元数据块（含可靠性/关联字段/库归属）→ 走「九、知识接入」（含跨库查重）→ 更新索引
- 回流产出形态：学习笔记 / 方法建议书 / 主题知识卡 / 错题卡 / 复盘报告，走 `知识库/系统/templates/` 同一套模板
- 回流不是可选动作：**每次产出必须落地到库**（索引与实际文件一致是检查项）
