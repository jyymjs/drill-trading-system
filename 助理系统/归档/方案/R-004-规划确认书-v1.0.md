## 一、需求理解摘要

当前风险信息**三处断链**：① risk-alert 风险检查点每次 🔔 提示后无登记无跟踪，提示完即消失；② 教训档案（坑卡）与风险无关联，预防措施没有风险锚点，风险发生也无法追溯对应教训；③ 内审部月审计（越权/分级准确性）结果只写进月体检报告，发现问题无统一落点、无后续跟踪。

本方案建立**统一风险登记台账**（新档案，档案室第 9 类档案），打通"登记 → 处理 → 闭环"全链条：risk-alert 每次提示、内审部每月审计发现、对话中识别的风险、教训落库四种来源全部入账；台账与教训档案双向映射；月体检固定扫描台账完成闭环与归档。职责三方分工：总裁办登记执行、老板/助理按档位闭环拍板、内审部监督审计。纯对话式（无后台服务），不新增部门/角色，不碰交易系统文件。

## 二、职责分工（三方，老板拍板）

| 角色 | 职责 | 说明 |
|---|---|---|
| **总裁办（助理）** | 登记执行 | risk-alert 提示即登记、对话识别入账、教训沉淀入账——唯一每轮对话在场的角色，登记不假手他人 |
| **老板** | 闭环拍板（问题类，C 档） | 内审部审计发现等需处理/跟踪的风险，闭环须老板确认 |
| **助理** | 闭环拍板（提醒类，A 档） | 提示一次即完成使命的提醒类风险，助理自主判定闭环 |
| **内审部（优化者）** | 监督审计 | 月审计查台账质量（登记是否真实/完整/无遗漏）；越权/分级记录入账 |
| **档案室（助理管理）** | 存放 | 台账为第 9 类档案，存 `助理系统/档案/风险台账.md` |

与 Q2 闭环二分法一致：提醒类 A 档（助理判定）、问题类 C 档（老板确认）。

## 三、方案要点

### a. 统一风险登记台账（新档案：`助理系统/档案/风险台账.md`，第 9 类档案）

**轻量化条目格式（≤1 行，宁可少而真实）**：

```
| F-序号 | 日期 | 类型 | 预警一句话 | 处理/状态 | 关联教训(可空) |
```

- 登记动作上限 1 行：时间 + 类型 + 一句话预警 + 状态；处理过程不展开记，需追溯时引用来源
- 字段说明：
  - 编号：F-序号，顺序累加
  - 类型：六类固定——交易资金 / 健康作息 / 财务生活 / 决策 / 规则 / 目标（漂移·冲突，挂 P-002，与 R-003 互引）
  - 来源：① risk-alert 提示 ② 内审部审计 ③ 对话识别 ④ 教训沉淀（表头注明，条目可不重复列）
  - 处理/状态：暴露中 → 处理中 → 已闭环 → 已归档
- 台账头部附登记规范（谁写、何时写、≤1 行怎么写），档案室（助理）维护

### b. 四个来源的入账规则（登记执行=总裁办）

| 来源 | 触发 | 入账动作 |
|---|---|---|
| ① risk-alert 提示 | 每轮对话检查点激活 🔔 | 提示时顺手登记一行（≤1 行，不打断对话；沿用"同对话同领域只登记一次"） |
| ② 内审部审计发现 | 每月审计（越权/分级不准确） | 审计结果由助理登记为风险项（多为"决策/规则"类），处理=按审计制度转 C 档上呈或领域锁定 |
| ③ 对话识别 | 对话中发现风险信号/老板自述风险 | 当场登记 |
| ④ 教训沉淀 | 新坑卡落库（需求结案归因/对话提炼） | 登记对应风险项，预防措施即处理结果，关联教训填坑卡编号 |

### c. 教训 ↔ 风险双向映射

- **教训档案改造**：每条坑卡新增"关联风险类型"列（例：2026-08-02 执行确认机制教训 → 关联"决策/规则"类），标识该预防措施守护的风险域
- **风险台账**：每条风险"关联教训"字段可追溯预防措施来源
- 双向可查：风险处理时引用对应坑卡纪律（risk-alert 的"引用纪律"逻辑不变）；坑卡查得到它防的是哪类风险

### d. 闭环机制（状态机，与职责分工一致）

- 状态流转：暴露中 →（开始处理）处理中 →（处理完成）已闭环 →（保留 3 个月后）已归档（移入 `归档/`）
- 闭环判定分两类：
  - **提醒类**（提示一次即完成使命）：助理自主判定闭环（A 档）
  - **问题类**（需处理/上呈/需跟踪，如内审部发现的越权）：处理完成后**老板确认**闭环（C 档上呈，随月度汇报或专项呈报）
- 未闭环风险 = 持续跟踪对象，每次月体检重新过一遍

### e. 月体检闭环扫描 + 内审部监督审计

- 月体检固定检查项新增"风险台账扫描"：① 未闭环风险逐条过（继续跟踪 or 提交老板判定）→ ② 已闭环满 3 个月归档 → ③ 输出台账月报：类型分布、高频领域、未闭环清单（呈报老板摘要，不逐条打扰）
- **内审部监督**（助理规则第十四节审计制度同步）：内审部月审计除既有项（越权/分级准确性）外，新增**查台账质量**——登记是否真实、完整、无遗漏；审计证据源扩展：R-002 讨论机制的变更日志/采纳驳回标注（规则风险可追溯）
- 高频领域建议沉淀入偏好/教训档案（沿用 risk-alert 既有规则，数据源改为台账）

### f. 与 risk-alert 风险检查点衔接

- risk-alert 技能新增"提示即登记"规则（提示块输出后，同领域当次会话内顺手登记台账）
- 台账成为 risk-alert 的引用数据源之一（提示依据仍优先引用教训档案，不变）
- 断链闭合：原来"提示完就没了"，现在每次提示留痕可查

### g. 跨需求联动

- **R-002（需求讨论机制）**：讨论机制的变更日志、采纳/驳回标注作为内审部审计的证据源——规则风险可追溯（哪条规则因何讨论而改、被谁驳回，台账风险可挂证据）
- **R-003（战略目标管理）**：新增"目标（漂移·冲突）"风险类型，挂 P-002 月度对标，与 R-003 方案互引（R-003 定标 → 台账监测漂移；台账发现漂移 → 反哺 R-003）

### h. 与其他制度衔接（不动机制，只加落点）

- 审计制度（助理规则第十四节）：审计结果除写月体检报告外，同步入账台账；新增台账质量检查项
- 月体检（助理规则第五节）：增加台账扫描项
- 组织架构内审部职责行：补"审计结果入风险台账"半句（门面同步）
