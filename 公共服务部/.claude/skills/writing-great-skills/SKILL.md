# 编写优质技能

技能是封装在 `.claude/skills/` 下的可复用流程。写好技能 = 一次投入，持续收益。

## 技能结构

```
.claude/skills/<技能名>/
├── SKILL.md          # 主文件（唯一必需）
├── <辅助文件>.md     # 可选：详细指南、示例、模板
└── scripts/          # 可选：配套脚本
```

## SKILL.md 规范

### 文件头（YAML frontmatter，必需）

```yaml
---
name: <kebab-case-name>
description: <一句话说明技能做什么 + 何时使用>
---
```

`name` 必须与目录名一致，`description` 用于决定何时加载此技能。

### 主体内容

- **第一段**：一句话概括技能目标
- **核心流程**：分步骤，每步有明确输入→输出
- **示例/模板**：如有输出格式要求，给出具体模板
- **边界条件**：什么情况下此技能不适用

## 质量检查清单

- [ ] `name` 与目录名一致
- [ ] `description` 能让人判断"我该不该用这个技能"
- [ ] 有清晰的分步流程（不是散文式描述）
- [ ] 有具体的输入→输出示例
- [ ] 标注了不适用场景
- [ ] 无过时引用（工具名、文件名、API 名）
- [ ] 引用的辅助文件确实存在
- [ ] 长度适中（50-200 行，太长→拆分子文件）

## 反模式

- ❌ description 写成标签堆砌（"代码、审查、质量、测试"）
- ✅ description 写成场景指引（"当用户要求审查代码时使用——执行代码标准+需求验收双轴审查"）
- ❌ 主体是概念论文（"为什么要做 X" 长篇大论）
- ✅ 主体是操作手册（"第一步做什么、第二步做什么"）
- ❌ 引用不存在的工具或文件
- ❌ 与其它技能功能高度重叠
